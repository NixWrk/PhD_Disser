# cardio-model-py

`cardio-model-py` — Python-порт вычислительного ядра проекта
[`WolframMath-master`](../WolframMath-master), посвящённого совмещению
радиальной импедансной кардиографии с геометрией сердца, полученной по МРТ.

Основная решаемая задача: по пяти радиальным импедансным каналам оценить
перемещение границы сердца, построить систолический контур и вычислить
изменение объёма относительно диастолического контура.

Это исследовательский программный код. Он воспроизводит математические
решения исходного Wolfram-проекта, но сам по себе не является
сертифицированным медицинским изделием и не должен использоваться для
клинических решений без отдельной валидации модели и исходных данных.

## Текущий статус

Реализован центральный вычислительный путь:

1. аналитические модели импеданса;
2. обратный табличный поиск параметров;
3. три используемых варианта оценки радиального движения;
4. подгонка эквивалентной сферы по МРТ-контуру;
5. построение систолического контура;
6. интерполяция контура и расчёт объёма;
7. сборка полного моделирования для трёх пациентов.

После аудита семантики Wolfram-кода исправлены четыре расхождения:

- `Round[x, 1]` теперь правильно трактуется как округление объёма до
  целого миллилитра;
- в `RadEvalMethod4` округляется только промежуточное `dr`, но не результат
  последующего геометрического преобразования;
- в совместной подгонке центра и радиуса действительно применяются
  ограничения Wolfram `-40 ≤ x ≤ 40`, `-60 ≤ y ≤ 40`, `20 ≤ r ≤ 60`;
- шаг сечений может быть вещественным и повторяет
  `Table[{i, 1, 101, step}]`.

Полный набор содержит **235 тестов**. Все 36 результатов `TotalModelling`
для Ivan, Alex и Artem строго совпадают с числами, сохранёнными в
`SphereMoveModelling.nb`.

Не реализованы и остаются явными заглушками:

- цифровая обработка сигналов в `dsp.py`;
- чтение реальных файлов РЕО-32 в `importers/reo32.py`;
- импорт COMSOL в `importers/comsol.py`;
- визуализация verbose-режимов в `plotting.py`.

STL/RFFI-часть исходного проекта отделена в
[`cardio-stl-repair`](../cardio-stl-repair) и не входит в этот пакет.

## Быстрый запуск

Требуется Python 3.10 или новее.

```powershell
cd cardio-model-py
python -m pip install -e ".[dev]"
python -m pytest -q
```

Расчёт одного варианта:

```python
from cardio_model.pipeline import radial_evaluation

sv = radial_evaluation(
    name="Ivan",
    sistole_method="None",
    eq_sphere_method="Use_Contour",
    rad_eval_method="FirstLayer_CenterMove",
)
print(sv)  # 14.0 мл
```

Перебор всех двенадцати вариантов:

```python
from cardio_model.pipeline import total_modelling

result = total_modelling("Artem")
print(result)
```

Индексация результата:

```text
result[sistole_method][eq_sphere_method][rad_eval_method]

sistole_method:
    0 = None
    1 = ValveMove

eq_sphere_method:
    0 = Use_Contour
    1 = Use_Contour_Radius

rad_eval_method:
    0 = None
    1 = FirstLayer
    2 = FirstLayer_CenterMove
```

## Контракт единиц измерения

Самая опасная граница в проекте — одновременное использование метров и
миллиметров.

| Значение | Единицы | Где появляется | Где используется дальше |
|---|---:|---|---|
| `zBase`, `dZRad`, `flDZ` | Ом | `data/patients.py` | `finders.py`, `radial.py` |
| `rho1`, `rho2` | Ом·м | модели и finders | `models.py` |
| `a`, `b`, `R`, `h`, `x`, `y` | м | `PARAMS` | `models.py`, `finders.py` |
| `dr`, `radial_move` | м | `radial.py` | умножается на 1000 в `pipeline.py` |
| МРТ-контуры | мм | `data/patients.py`, `data/mri.py` | `sphere_fit.py`, `sistole.py`, `geometry.py` |
| `center_move`, `dxdy` | мм | `pipeline.py` | Method4 делит их на 1000 |
| `valve_move` | мм | `data/mri.py` | `sistole.py` |
| длина хорды, `h_step` | мм | `geometry.py`, `volume.py` | объём усечённого конуса |
| промежуточный объём | мм³ | `cut_konus_circle_volume` | делится на 1000 |
| `VolumeByContour`, `SV` | мл | `volume.py`, `pipeline.py` | конечный результат |

Правила преобразования:

- `radial_move` переводится из метров в миллиметры ровно один раз:
  `-radial_move * 1000`;
- локальное смещение центра перед передачей в импедансную модель переводится
  обратно из миллиметров в метры: `dxdy / 1000`;
- `1 мл = 1000 мм³`;
- координаты МРТ не следует передавать напрямую в `sphere_model`.

## Входные данные

### Импедансные данные

Файл `src/cardio_model/data/patients.py` содержит для каждого пациента:

| Ключ | Форма | Содержание | Следующий потребитель |
|---|---:|---|---|
| `dZRad` | `(5,)` | изменение импеданса пяти каналов | `rad_eval_method1/2/4` |
| `zBase` | `(5,)` | базовый импеданс пяти каналов | поиск `rho1` и `dr` |
| `flDZ` | скаляр | изменение импеданса первого слоя | `find_ro_one` в Method2/4 |
| `flBase` | скаляр | исторический параметр исходной Association | в текущих Method1/2/4 не используется |

### Параметры пяти каналов

Каждый из массивов `a`, `b`, `R`, `h`, `x`, `y` имеет пять элементов:
один набор геометрии на один импедансный канал.

- `a`, `b` задают полуоси модельного сечения тела;
- `R` — начальный радиус сферической модели сердца;
- `h` — глубина центра сферы;
- `x`, `y` — положение центра относительно электродной геометрии;
- `flSize=[a_fl, b_fl]` используется для оценки изменения сопротивления
  первого слоя;
- `hFat` сохранён из Wolfram-данных, но в текущих трёх радиальных методах
  непосредственно не участвует.

### Контуры и движения

`get_contour(name)` возвращает семь точек диастолического контура в
миллиметрах. Первая и последняя точки относятся к зоне клапанного кольца,
пять внутренних точек соответствуют пяти импедансным направлениям.

Файлы `data/moves/*.txt` содержат пять временных рядов движения края.
`edge_move_5pt` берёт последний элемент каждой строки и меняет знак, как
`-Map[Last, HeartEdgeMoving[person]]` в Wolfram.

`VALVE_MOVE` хранит отдельное смещение линии клапана. Оно применяется
только при `sistole_method="ValveMove"`.

Геттеры данных сейчас возвращают ссылки на хранимые массивы. Если вызывающий
код собирается их изменять, необходимо сделать копию:

```python
contour = get_contour("Ivan").copy()
params = {key: value.copy() if hasattr(value, "copy") else value
          for key, value in get_param("Ivan").items()}
```

## Этап 1. Прямые модели импеданса

Реализация находится в `models.py`, Wolfram-источник —
`Kernel/core/Models.m`.

### Однослойная модель

```text
Z = ρ1 · 2b / (π · (a² - b²))
```

`one_layer_model` преобразует геометрию однородного проводящего сегмента и
удельное сопротивление ткани в импеданс. В дальнейшем обратная формула
используется функцией `find_ro_one`.

### Двухслойная модель

`two_layer_model` добавляет к базовой формуле бесконечный в исходной
постановке ряд, обрезанный при `n=100`, как и в Mathematica. Модель
сохраняется для обратного поиска толщины слоя `find_h_two`.

### Сферическая модель сердца

```text
SphereModel = OneLayerModel + SphereInfluence
```

`SphereInfluence` собирается из четырёх слагаемых `Zep` с разными
расстояниями и знаками. В каждом `Zep` используется ряд полиномов Лежандра:

```text
Σ n=0..100 [
    (R/rp)^(n+1) · (R/re)^n ·
    n(ρ2-ρ1) / ((n+1)ρ2+nρ1) ·
    Pn(cos θ)
]
```

Эта функция является основой всех обратных поисков `R`, `h`, `rho1` и
`dr`. Аргументы геометрии здесь всегда задаются в метрах.

## Этап 2. Обратные задачи

Файл `finders.py` воспроизводит шаблон Wolfram:

```text
Table → Partition по соседним точкам → поиск первого изменения знака
```

Найденный результат — левый конец первого интервала пересечения. Это не
интерполяция корня и не непрерывная оптимизация. Точность результата
ограничена шагом сетки.

| Функция | Искомое | Диапазон и шаг | Где используется |
|---|---|---|---|
| `find_ro_one` | `rho1` | аналитическая формула | Method2/4 |
| `find_h_two` | толщина `h` | 0…0.05, 0.0005 м | отдельные исследования |
| `find_r_sphere` | радиус `R` | 0…0.1, 0.0005 м | служебный API |
| `find_h_sphere` | глубина `h` | 0…0.05, 0.0005 м | служебный API |
| `find_ro_sphere` | `rho1` | 0.1…50, 0.05 Ом·м | все поиски `dr`, если `ro1=0` |
| `find_dr_sphere` | уменьшение радиуса | 0…0.02, 0.0001 м | Method1 |
| `find_dr_sphere_fl` | `dr` и первый слой | 0…0.02, 0.0001 м | Method2 |
| `find_dr_sphere_fl_dxdy` | `dr`, слой и центр | -0.02…0.02, 0.0001 м | Method4 |

Смещения `bias=±0.0001`, направления пересечения и возврат левой точки
сохранены из исходного кода намеренно.

Если пересечения на заданной сетке нет, Python выбрасывает `ValueError`.
Это более явная диагностика, чем последующая ошибка индексации в Wolfram.

## Этап 3. Радиальная оценка движения

Файл `radial.py` преобразует пять пар `(zBase, dZRad)` в пять радиальных
перемещений.

### Method1 — `rad_eval_method1`

Для каждого канала:

1. по `zBase` находится эффективное `rho1`;
2. по `dZRad` находится уменьшение радиуса `dr`;
3. `dr` округляется к кратному `0.0001 м`.

Результат используется как радиальное движение края без поправки первого
слоя.

### Method2 — `rad_eval_method2`

Сначала по `flDZ` вычисляется `dro1`. Затем поиск `dr` выполняется между
состояниями `rho1` и `rho1-dro1`. Итог также округляется до `0.0001 м`.

### Method4 — `rad_eval_method4`

Method4 добавляет перемещение центра сферы:

1. локальные `dx`, `dy` переводятся из миллиметров в метры;
2. `find_dr_sphere_fl_dxdy` ищет промежуточное `dr`;
3. только `dr` округляется до `0.0001 м`;
4. вычисляется геометрически скорректированное движение:

```text
result = R - sqrt((R - dr)² - dx²) - dy
```

Итог `result` повторно не округляется. Это существенная особенность
Wolfram `RadEvalMethod4`: дополнительное округление меняет контур и объём.

## Этап 4. Эквивалентная сфера по МРТ

Файл `sphere_fit.py` работает уже в миллиметрах.

Целевая функция:

```text
SumDelta(center, r) = Σi (|point_i - center| - r)²
```

Методы `equal_sphere`:

| Метод | Что оптимизируется | Что фиксировано | Где используется |
|---|---|---|---|
| `Use_Contour` | центр и радиус | ничего | `TotalModelling` |
| `Use_Contour_Radius` | только радиус | центроид полигона | `TotalModelling` |
| `Use_Contour_Center` | только центр | переданный радиус | вспомогательный режим |
| `Use_Contour_MassCenter` | нет оптимизации | центроид и радиус по площади | быстрые проверки |

Для `Use_Contour` действуют исходные ограничения:

```text
-40 ≤ center_x ≤ 40 мм
-60 ≤ center_y ≤ 40 мм
 20 ≤ radius   ≤ 60 мм
```

Оптимизатор — `scipy.optimize.minimize(method="Nelder-Mead")`. Начальная
точка строится по среднему координат и среднему расстоянию, после чего
ограничивается допустимой областью.

`equal_sphere_move_modelling` подгоняет сферу отдельно к диастолическому и
систолическому контурам и возвращает:

```text
center_move = center_sistole - center_diastole
```

## Этап 5. Проекция движения центра на пять каналов

`h_contour_dxdy_for_each_channel` берёт пять внутренних точек
семиточечного контура. Для каждой точки `dxdy_find` проецирует общий
вектор `center_move` в локальную систему данного канала.

Получается массив формы `(5, 2)` в миллиметрах. В Method4 его столбцы
передаются в переставленном порядке, потому что именно такой порядок
использует исходный `RadialEvaluation.m`.

Проекция использует абсолютный угол, поэтому знак поперечной компоненты не
содержит полной ориентации 2D-вектора. Это свойство исходного алгоритма,
а не изменение Python-порта.

## Этап 6. Систолический контур

Файл `sistole.py` получает диастолический контур и пять внутренних
перемещений.

`sistole_none`:

1. добавляет к пяти движениям граничные значения для первой и последней
   точки;
2. переводит точки в полярные координаты;
3. изменяет радиусы;
4. возвращает декартовы координаты.

`sistole_valve_move` сначала выполняет тот же радиальный сдвиг, затем
перемещает первую и последнюю точки по нормали к линии клапанного кольца.
Пять внутренних точек при клапанной поправке не меняются.

В верхнем пайплайне используется:

```python
sistole_contour(
    contour,
    -radial_move * 1000.0,
    valve_move,
    sistole_method,
)
```

Минус и множитель 1000 унаследованы от Wolfram: результат радиальной
инверсии имеет противоположное направление и задан в метрах.

## Этап 7. Интерполяция и параллельные сечения

`kubic_interpol` в `geometry.py` воспроизводит кубическую эрмитову
интерполяцию `KubicInterpol`.

Для семи узлов:

1. вычисляются длины шести хорд;
2. собираются матрицы `MatrixM` и `MatrixR`;
3. решается СЛАУ для производных в узлах;
4. крайние производные заменяются значениями `fringe`;
5. каждый из шести интервалов вычисляется в 31 точке.

Результат содержит `6 · 31 = 186` точек. Границы соседних интервалов
дублируются, как в исходной реализации.

`get_l_point` проводит линию, параллельную линии между первой и последней
точками, и ищет смены знака между соседними дискретными точками. Функция
возвращает концы пересекаемых сегментов, а не аналитически вычисленные
точки пересечения.

`list_of_parallel_sections` вызывает `get_l_point` для сетки:

```text
1, 1 + h_step, 1 + 2·h_step, ... ≤ 101
```

`h_step` может быть вещественным. Он обязан быть положительным и конечным.

## Этап 8. Объём и ударный объём

Длина каждой хорды трактуется как диаметр кругового сечения. Между двумя
соседними диаметрами используется формула усечённого конуса:

```text
V = πh/12 · (d1² + d1·d2 + d2²)
```

Если размеры заданы в миллиметрах, результат одного слоя получается в
мм³. Сумма делится на 1000 для перевода в мл.

После суммирования применяется:

```wolfram
Round[Total[volumes] / 1000, 1]
```

В Wolfram второй аргумент — квант округления. Поэтому Python возвращает
целое число миллилитров в типе `float`, например `604.0`, а не `604.2`.

Несмотря на имя опции `SimpsonMethod -> "Circle"` в исходнике, данная
формула является формулой объёма усечённого конуса, а не квадратурой
Симпсона.

Конечный расчёт:

```text
SV = (Volume(diastole) - Volume(sistole)) / 2
```

Каждый из двух объёмов округляется до целого до вычитания. Поэтому SV
может иметь шаг `0.5 мл`.

Деление на два перенесено из Wolfram без изменения. Его физиологическое
обоснование в исходных файлах явно не документировано.

## Этап 9. Верхний API

### `equal_sphere_move_modelling`

Использует МРТ-движение края, строит систолу, подгоняет две сферы и
возвращает движение центра. Результат далее нужен только варианту
`FirstLayer_CenterMove`.

### `radial_evaluation`

Полный расчёт одной комбинации:

1. получает движение центра по МРТ;
2. проецирует его на пять каналов;
3. выбирает Method1, Method2 или Method4;
4. строит систолический контур;
5. рассчитывает два объёма;
6. возвращает `(Vd-Vs)/2`.

### `total_modelling`

Перебирает:

- два способа движения клапана;
- два способа подгонки сферы;
- три метода радиальной оценки.

Итого получается 12 результатов на пациента.

## Верификация

Основные уровни проверки:

- формулы прямых моделей и частные аналитические случаи;

- геометрические инварианты интерполяции и систолы;

## Ограничения и научные допущения

Следующие свойства не являются ошибками переноса: они присутствуют в
исходной модели и сознательно сохранены.

1. Ряды обрезаются при 100 членах без автоматического контроля сходимости.
2. Обратные поиски возвращают левую точку сеточного интервала, а не
   интерполированный корень.
3. Контурные пересечения оцениваются по дискретным сегментам
   186-точечной интерполяции.
4. В объёмной модели каждая хорда считается диаметром круга.
5. До вычитания диастолический и систолический объёмы округляются отдельно.
6. В формуле SV присутствует жёсткое деление на два.
7. Проекция `dxdy_find` использует абсолютный угол и теряет ориентационный
   знак поперечной компоненты.
8. Для геометрии сферы не выполняется отдельная проверка области сходимости
   ряда Лежандра.
9. Данные представлены только для трёх пациентов; это не статистическая
   или клиническая валидация.
