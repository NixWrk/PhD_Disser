Первичный RR-разбор выполняет
[analyze_subtraction_and_rr.py](../analyze_subtraction_and_rr.py).
Скрипт читает внешние `phases/conversion_manifest.json`, `automatic_masks_v2`,
`products_v2`, сводку временных метаданных КТ и свидетельства GE ECG Report.

| Артефакты | Назначение |
|---|---|
| `*_heart_minus_blood_4d.html` | Синхронный просмотр 3D-геометрии, временной координаты и объёмов |
| `*_chamber_volumes_rr.html` | Отдельные графики объёмов |
| `cardiac_dicom_metadata_by_subject.csv`, `cardiac_gating_source_data.csv` | Метаданные КТ и отдельные интервалы из R-меток GE |
| `chamber_volumes_by_rr.csv` | Объёмы по реконструированным фазам |
| `chamber_volume_changes_measured_cycles.csv` | Изменения между имеющимися фазами отдельных циклов |
| `chamber_volume_changes_closed_cycle.csv`, `chamber_volume_changes_closed_cycle_summary.csv` | Модельные периодические профили и сводка; Georg не включён в композит |
| `rr_and_subtraction_summary.json` | Происхождение расчёта, определения, ограничения и статусы |
| `ecg_traces/*.png`, `ecg_traces/manifest.json` | Растровые полосы GE; готовит отдельно `extract_deidentified_ecg_trace.py` |

`ecg_traces` содержит растровое представление, а не калиброванную цифровую
ЭКГ. Эта папка относится к кардиосинхронизации КТ и не является результатом
детектора R-зубцов реокардиомониторов серии `11`.

Файлы notebook/HTML `21.03` находятся уровнем выше. Их iframe-ссылки требуют
сохранения этой папки рядом с ними. Команды воспроизведения и различия между
raw-объёмами, обработанной кровью и 3D-поверхностями приведены в `21.00`.
Автоматические маски остаются кандидатными; геометрический остаток
«сердце минус кровь» не является валидированным полным миокардом.

### Входы индексации по площади тела

[cardiac_reference_indexing.py](../cardiac_reference_indexing.py) читает
`function_analysis/reference_indexing/anthropometry.local.json`.
Минимальная структура файла имеет вид:

```json
{
  "subjects": {
    "<subject_id>": {
      "height_cm": null,
      "weight_kg": null,
      "age_years": null,
      "sex": null
    }
  },
  "provenance": {
    "source_kind": "указать источник сведений",
    "anthropometry_at_CT_confirmed": false,
    "age_at_CT_confirmed": false
  }
}
```

Вместо `<subject_id>` указывается идентификатор из исходной таблицы.
Рост задаётся в сантиметрах, масса — в килограммах, возраст — в годах;
значения пола в конфигурации — `male` или `female`. Пропуски `null` не
заменяются средними или данными другого испытуемого. Для вычисления BSA
нужны положительные конечные рост и масса; возраст и пол не меняют формулу.
Сведения об источнике, дате и применимости к исследованию фиксируются
в `provenance` и сохраняются в манифесте результата.

Текущий набор референсов ограничен мужчинами 20–29 лет. Если пол или возраст не соответствуют этой
группе либо не указаны, объёмы индексируются при наличии роста и массы,
но референс не выбирается. При отсутствии роста либо массы соответствующий
испытуемый пропускается. Сейчас сведения заданы только для Nix, взяты из
выписки диалога и не подтверждены первичным протоколом на дату КТ.
Личные числовые значения не дублируются в этой инструкции.

Выходы `indexed_estimates.csv` и `reference_values.json` содержат результаты
и выбранные таблицы; единицы показателей указаны в CSV. `manifest.json`
фиксирует происхождение, статусы и контрольные суммы. ФВ сохраняется в процентах, объёмы делятся на BSA.
Индексированный УО и положение относительно МРТ-референса остаются условными;
правила включения папиллярных мышц в референсах ЛЖ и ПЖ различаются.
Числовая близость к референсу не определяет правильность маски.

### Обновление и доступность файлов

Из родительской папки `cardiac_4d_segmentation`:

```powershell
python build_cardiac_function_report.py --presentation-only
```

Прежние численные результаты сверяются по контрольным суммам и используются
без повторного расчёта; BSA-индексы вычисляются отдельно по текущей локальной
конфигурации. Отсутствие файла антропометрии приводит к пропуску индексации.
Отсутствие обязательных кэшей, манифестов или результатов совместного анализа
останавливает сборку. Режим не восстанавливает отсутствующие КТ или маски.
При наличии лишь сохранённого notebook доступен простой экспорт HTML,
описанный в [README серии](../README.md).

Данные КТ, новые маски, локальные конфигурации и содержимое `function_analysis`
не добавляются в Git вместе с обновлением документации. Исторические
21.04–21.07 сохраняют методические сведения; текущие решения об отсутствии
нового ручного референса и статусе УО/ФВ описаны в основном 21.03.
