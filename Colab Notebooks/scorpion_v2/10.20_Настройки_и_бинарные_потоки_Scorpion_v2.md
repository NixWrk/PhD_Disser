# 10.20 Настройки и бинарные потоки Scorpion v2

**Назначение:** установить структуру BIN, связать их с TXT по самим данным
и уточнить основания временной шкалы. Это технический этап серии `10`;
дыхательная и ЭКГ-разметка остаётся у [11.20](11.20_Просмотр_и_разметка_Scorpion_v2.md).

## Изменение исходной классификации

Первоначально по сообщению автора BIN были классифицированы как настройки,
не нужные для анализа сигналов. По новому запросу автора от 07.10.2026
выполнен полный побайтовый разбор: семь файлов пусты, три содержат
пакетные потоки с измерениями и сообщениями параметров. Предыдущее исключение
BIN из набора физиологических входов не означало проверки их содержимого.
Для текущего просмотра входами остаются 18 TXT; BIN используются как
дополнительное первичное основание происхождения и настроек этих записей.

## Проверенные наблюдения

- Разделитель `00`, кодирование совместимо с COBS. Пакеты `0x10` имеют
  длину `15 + 22 × n`, где наблюдались `n = 1` и `n = 8`.
- В `0x10` байт +1 совпадает с COUNT, поля +2…+4 и +5…+7 — знаковые
  24-битные числа little-endian, соответствующие двум экспортированным ЭКГ.
- Пакеты `0x11` длиной 22 и 64 байта повторяют параметры. Поля сохраняются
  с числовыми смещениями; их назначения не восстанавливаются по одному
  похожему числу. Два последних байта пока не проверены как контрольная сумма.
- В потоке найдено версионное сообщение `0.001` и время сборки
  `Sep 24 2026 18:55:17`. Его принадлежность конкретному компоненту
  требует подтверждения разработчика.
- Полные участки 16 TXT найдены в BIN. Для каждого совпадают COUNT во всех
  строках и обе ЭКГ при фиксированном множителе `0,001 мВ/целое число BIN`
  с остатком не более `0,005 мВ`, то есть половины шага текстового округления.
  Это эмпирическое соответствие файлов, а не метрологическая калибровка.
- Для `001` и `002` соответствующий участок BIN в этой загрузке не найден.
  Это не доказательство отсутствия регистрации на приборе.

## Рабочая интерпретация временной шкалы

Поле u16 +2 равно 2500 на всём протяжении `005` и `006`, 1000 — в
`003`, `004`, `007–018`. Если оно задаёт период отсчёта в микросекундах,
`fs = 10⁶ / значение`, то есть соответственно 400 и 1000 Гц.
В длинном BIN переход 2500 → 1000 расположен между `006` и `007`.

Эту интерпретацию поддерживает дополнительный технический ориентир: между
концами `005/006` в BIN 58 472 пакета, времена TXT в ZIP различаются на 146 с,
что даёт около 400,49 Гц. Для концов `007/018` соответствующие числа
3 123 286 и 3124 с дают около 999,77 Гц. Время изменения файла — ориентир
экспорта с ограниченной точностью; оно не является приборной шкалой измерения
и не подтверждает точность тактового генератора. Этот довод не требует
считать сильную спектральную линию сетевой помехой.

Для `005/006` рабочая длительность `N/fs` равна 81,0625 и 82,2425 с.
Для `001/002` сохраняется только сообщённое автором значение по умолчанию
1000 Гц. Значение и единица поля +2 ещё не подтверждены протоколом прибора;
рабочую частоту отличать от независимо задокументированной настройки.
Предыдущие сценарии 1000/400 Гц в просмотре сохранены для сравнения.

## Остальные настройки и ограничения

В одноблочном состоянии группа u32:u16 от +14 содержит `100000000:7000`.
Первое число совместимо с подтверждёнными автором 100 кГц, если единица —
мГц; эта единица пока гипотеза. Значение 7000 не интерпретируется как ток
или усиление. При смене поля +2 меняются также +4 и +10:
`1000/1300` для 2500 и `450/550` для 1000. Фильтры, интеграция,
диапазоны и паузы из этих чисел не установлены.

Физический смысл BPH, CE и CPH, аппаратная фильтрация и межканальные задержки
остаются неизвестными. Дополнительные участки BIN не включаются автоматически
в физиологический анализ. Частичный начальный пакет и один внутренний
неразобранный блок длинного BIN отмечены в QC; разрыв COUNT находится вне
найденных TXT. Семь пустых BIN не объявляются потерянными сигналами.

## Воспроизводимость

Код: [структура](inspect_scorpion_bin.py), [сопоставление](match_scorpion_bin.py),
[отчёт](build_scorpion_bin_report.py), [проверки парсера](test_scorpion_bin.py).
Исходные TXT читаются непосредственно из `raw` с проверкой SHA-256;
BIN также проверяются относительно первоначального манифеста. Все
индивидуальные массивы и таблицы сохраняются в исключённом из Git
`Experiments/scorpion_v2_georg/derived/scorpion_bin_review/`.

```powershell
python -B -X utf8 "Colab Notebooks/scorpion_v2/inspect_scorpion_bin.py" --experiment "Experiments/scorpion_v2_georg"
python -B -X utf8 "Colab Notebooks/scorpion_v2/match_scorpion_bin.py" --experiment "Experiments/scorpion_v2_georg"
python -B -X utf8 "Colab Notebooks/scorpion_v2/build_scorpion_bin_report.py" --experiment "Experiments/scorpion_v2_georg"
```

При подтверждении разработчиком исправлять расшифровку отдельной ревизией
со ссылкой на протокол. Не принимать автоматически дыхательную/QRS-разметку
и не считать техническое соответствие валидацией расчёта УО/ФВ.
