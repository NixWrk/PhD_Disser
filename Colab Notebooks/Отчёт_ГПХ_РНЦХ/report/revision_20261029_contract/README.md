## Границы результата

Наличие раздела не подтверждает автоматически положительное требование к УО. Модельные тесты, геометрические проверки, обработка реальных записей и проверка конечного физиологического показателя имеют разные статусы. Все обнаруженные отрицательные результаты и ограничения сохраняются.

Полные медицинские данные, аннотированные маски, STL и расчётные архивы описаны по исторической описи и не создаются заново этой редакцией. Их актуальная комплектность требует проверки самих файлов. Презентация — отдельный результат договора, не включённый в текущую редакционную поставку. Новые физические расчёты и новые экспериментальные измерения при переработке текста не выполняются.

## Сборка и рецензирование

Сборка выполняется `tools/build_word.py` через Pandoc с нативными формулами Word. Сохранённые иллюстрации недоступных исходных каталогов разрешаются только по проверенным хэшам предыдущего манифеста. Недоступные исторические ссылки явно отмечаются.

Содержание обновлено средствами Microsoft Word; итоговая вёрстка проверяется по его PDF-экспорту. Автоматические проверки структуры выполняются с `--availability-manifest build_manifest.json`: недоступность 70 исторических ссылок явно отражена в тексте, а шесть прежних рисунков разрешены по сохранённым хэшам.

`tools/prepare_contract_revision.py`, `tools/frame_sv_report.py`, `tools/integrate_html_figures.py`, `tools/reorder_contract_chapters.py`, `tools/finalize_figures_and_layout.py` и `tools/correct_figure_reference.py` — однократные операции подготовки этой редакции; повторный запуск поверх отрецензированного текста не предусмотрен. Итоговый манифест и проверки размещаются в `deliverables/`.

После начала авторского рецензирования не заменять Word повторной сборкой из Markdown. Сначала сохранить авторскую версию и перенести принятые изменения с сохранением истории исправлений. Внутренние PDF и изображения страниц предназначены для контроля вёрстки, а не являются дополнительными результатами передачи.
