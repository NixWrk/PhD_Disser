**Установлено и проверено 28.09.2026 на Windows, Python 3.13.6.** Окружение
`.venv/` и исходный checkout `cache/source/` локальные и исключены из Git.
Исходный код MONAI Physio: коммит
`6822e3e3b3863c63fbc01f86f9c4676c4c47e596`, версия `2026.09.1`.

Проверки: импорт `monai_physio` возвращает `2026.09.1`, CUDA видна PyTorch;
`uv pip check` сообщил совместимость всех 241 установленных пакетов.
Работоспособность каждого вычислительного workflow этим не доказана: её
фиксируют отдельно в соответствующем ноутбуке.

При прямом запуске сегментации ITK в этом Windows-окружении не открыл NIfTI
по исходному пути с кириллическим компонентом. Чтение того же файла через
временный ASCII-псевдоним диска `subst` прошло, и обёртка дошла до вызовов
TotalSegmentator. Это локальное ограничение путей, а не ошибка КТ и не
доказательство завершения сегментации. Скрипт [MP-01](mp01_02_run_monai.py)
создаёт и удаляет такие псевдонимы в пределах запуска; его выходной каталог
должен оставаться внутри исключённой `runs/`.

Полный MP-01 на одной фазе затем завершился. Лицензированные веса Task 485
были получены с официального backend TotalSegmentator через локально
установленную академическую лицензию; публичные веса Task 117 — из точного
[release TotalSegmentator](https://github.com/wasserth/TotalSegmentator/releases/tag/v2.5.0-weights).
Launcher ограничивает сетевые запросы этими адресами и проверенным адресом
перенаправления Task 117. Исходная КТ в запросы не передаётся. Прежний
`WinError 10013` был ограничением sandbox network, а не доказательством
недействительности лицензии. Контрольные суммы входа и выходной карты,
версии и выполненные задачи сохранены в локальном ignored `runs/`.

## Проверка актуальности готовых весов, 07.10.2026

Версия программного пакета и версия весов учитываются отдельно. Новый выпуск
кода сам по себе не означает появление нового обученного checkpoint.

- **Дыхательное движение лёгких:** использованный архив
  `physicsnemo_mgn_lung_motion.zip` является единственным опубликованным
  архивом этих весов в девяти публичных релизах MONAI Physio на дату проверки.
  Официальный загрузчик версии `2026.09.1` ссылается на него. Архив добавлен
  17.09.2026 к релизу `2026.07.1`; его SHA-256
  `365d575e20e2fb03cd4940670816aaabc51c837779f61e48ff01977682283cdc`
  совпадает с контрольной суммой использованного архива. Июльская метка
  релиза не устанавливает дату обучения модели.
- **Прогноз кардиального движения:** использованы исторические готовые веса
  из тега `2026.07.3`. В релизе `2026.08.0` они удалены из репозитория;
  нового готового сердечного checkpoint в публичных release assets не найдено.
  Проверка относится к исторической модели. Выбор обусловлен требованием
  использовать готовые веса без обучения на проектных данных.
- **NV-Segment-CTMR:** использованный commit
  `4fb8b4a6b2532be9f1c449a3726fe5440ab4213a` совпадает с текущим commit
  официального репозитория модели NVIDIA на Hugging Face.
- **TotalSegmentator:** публичная Task 117 по-прежнему указана в официальной
  таблице загрузчика с весами `v2.5.0-weights`. Task 485 загружается через
  лицензированный backend без публичной версии архива. Независимая проверка
  неизменности всех лицензированных весов этой сверкой не выполнена.

## Как воспроизвести из папки `monai_physio/`

1. Создать отдельное окружение Python 3.13 и направить кэш `uv` в локальную
   исключённую папку `cache/` (обычный профильный кэш был недоступен на этом
   рабочем месте).
2. Установить PyTorch 2.12.0+cu126 из официального индекса PyTorch.
3. Установить совместимое готовое Windows-колесо `torch-scatter`
   `2.1.2+pt212cu126` из
   [официального индекса PyG](https://data.pyg.org/whl/torch-2.12.0+cu126.html).
   Без этого обычное разрешение зависимостей пыталось собирать пакет из
   исходников и завершалось отсутствием `torch` в build-окружении.
4. Получить исходники
   [MONAI Physio](https://github.com/Project-MONAI/monai-physio) именно указанного
   коммита в `cache/source/` и выполнить из них локальную установку с extra
   `cuda12`. Записывать фактический commit и версии при каждом новом запуске.

Эквивалентный минимальный порядок команд PowerShell (перед запуском проверить
совместимость версий CUDA и доступность источников):

```powershell
$env:UV_CACHE_DIR = (Join-Path (Get-Location) 'cache/uv')
uv venv .venv --python 3.13
uv pip install --python .venv/Scripts/python.exe --index-url https://download.pytorch.org/whl/cu126 'torch==2.12.0+cu126'
uv pip install --python .venv/Scripts/python.exe --no-deps 'https://data.pyg.org/whl/torch-2.12.0%2Bcu126/torch_scatter-2.1.2%2Bpt212cu126-cp313-cp313-win_amd64.whl'
# После получения зафиксированного исходного коммита в cache/source:
Push-Location cache/source
uv pip install --python ../../.venv/Scripts/python.exe -e '.[cuda12]' 'torch-scatter==2.1.2+pt212cu126'
Pop-Location
uv pip check --python .venv/Scripts/python.exe
```

Это установка пакетов и весов **для локального исследования**. КТ,
сегментации, обученные веса и большие производные выходы хранятся вне Git.
Не запускать автоматические примеры с загрузкой данных на проектных КТ без
отдельной проверки источника весов и лицензионных условий конкретных задач
TotalSegmentator.

Для локальной вращаемой 3D-визуализации верхней границы КТ Ника скрипт
`mp03_nix_fov_3d.py` дополнительно использует `plotly` (выполнено с 6.9.0),
`pyvista`, `trimesh` и `nibabel`. HTML/PNG сохраняются только в ignored `runs/`.
