# MATLAB_TRKG4_real_subjects — единый MATLAB/Python-pipeline моделей

> **Статус на 31.08.2026:** это единственная активная папка моделирования.
> Подтверждённые расчёты выполняются MATLAB/EIDORS/Gmsh и Python-скриптами.
> Исторический прототип перенесён в `archive/` и не является параллельным
> источником актуальных результатов.

Папка содержит прототип расчётов TRKG4 в MATLAB/EIDORS на анатомии реального
испытуемого. При этом чистый checkout не является самодостаточным: часть
принятых STL, prebuilt mesh и экспериментальные входы находятся вне Git.
Отдельной blood-маски для Nik нет по составу исходной сегментации: доступна
единая маска сердца. Документация трактует найденную точку как
регуляризованный локальный кандидат, а не доказанное уникальное решение.

До научного использования конкретного результата необходимо подтвердить
происхождение геометрии Inobitec, монтаж электродов, единицы, проводимости,
сетку, входной сигнал, параметры оптимизации, commit SHA и QC.

Полный отчёт: [AUDIT_2026-08-23.md](AUDIT_2026-08-23.md).

## Вычислительное окружение

На 31.08.2026 локально проверена следующая конфигурация:

- MATLAB R2025b;
- Statistics and Machine Learning Toolbox, Parallel Computing Toolbox,
  Optimization Toolbox и Image Processing Toolbox;
- EIDORS 3.12 с Netgen 5.3;
- Gmsh 4.15.2;
- Python 3.13 с пакетами из `requirements.txt`.

Машинозависимые пути не записываются в исходный код. Для локального запуска
используются пользовательские переменные среды:

- `EIDORS_STARTUP` — полный путь к файлу `startup.m` EIDORS;
- `GMSH_EXE` — полный путь к исполняемому файлу Gmsh;
- `KALMYKOV_DICOM_DIR` — необязательный путь к индивидуальной DICOM-серии,
  используемой только для HU-фона в Python-отчёте. Без него MATLAB/FEM-расчёт
  и геометрический STL-срез остаются доступными. Медицинские данные в Git не
  копируются;
- `BLENDER_EXE` — необязательный полный путь к Blender для старых операций
  подготовки и визуального QC STL. Если переменная не задана, PowerShell-
  обёртки ищут команду `blender` в `PATH`.

Функция `trkg4_prepare_runtime.m` загружает EIDORS и добавляет каталог Gmsh к
пути текущего процесса MATLAB. Если зависимость отсутствует, расчёт
останавливается с явным сообщением. Модульная проверка запускается командой

```matlab
addpath('src');
results = runtests('tests');
assertSuccess(results);
```

Один прямой FEM-расчёт на ранее принятой сетке также завершился, однако

# MATLAB_TRKG4_real_subjects

Цель папки — выполнять MATLAB/EIDORS-расчёты на реальных CT/STL-данных
испытуемых и формировать проверяемые артефакты для notebook-отчётов.

Активная постановка:

- расчёт идёт в MATLAB/EIDORS/Gmsh; Python используется для подготовки,
  проверки геометрии и оформления отчётов;
- геометрия берется из CT/STL испытуемого;
- используется только 4 электрода TRKG;
- сердце не аппроксимируется сферой;
- радиус сердца не меняется;
- мягкие ткани идут как фон, легкие/сердце/кости назначаются по STL-маскам;
- результатом является статический transfer impedance для заданной реальной
  расстановки 4 электродов.

## Что взято из STL-примера

Из `archive/MATLAB_investigation_NIX/ForwardSolutionWithStlGeometryExample(by_NIX)`
перенесены и затем проверены MATLAB-хелперы в `vendor_stl_eidors/`:

- назначение тканей по закрытым STL-маскам;
- проверка попадания точек внутрь STL;
- выбор граничных треугольников электрода по площади;
- диагностика того, куда фактически попал каждый электрод на поверхности;
- ITIS-проводимости;
- служебные функции для centroids/cache/parallel.

Большие STL, output, Gmsh и вложенный `.git` не копировались.

## Точки входа

```matlab
addpath('src')
```

| Скрипт | Что делает |
|---|---|
| `run_trkg4_forward_subject('nik')` | Один прямой расчёт на монтаже по умолчанию (руки). Простейшая проверка, что вход и сетка на месте |
| `run_trkg4_arm_electrode_tests()` | Параметрически задаёт внутренние и внешние электроды на руках, сравнивает 5-мм диски, кольца и эквивалентные большие манжеты, а также проверяет теорему взаимности на одной сетке и одном назначении тканей |
| `run_trkg4_electrode_systems()` | Сравнение трёх монтажей на **одной** сетке и одном назначении тканей, поэтому разница в `Z` вызвана только расстановкой. Пишет общую сетку в `output/nik_trkg4_<system>_full_v5_1mm_local2mm.mat` |
| `run_trkg4_inverse_inhale()` | Совместная подгонка `rho_soft`, `rho_lung` и позы решётки под многоразмерный эксперимент на вдохе |
| `run_trkg4_fast_pem_scan()` | Быстрый скан позы в приближении точечных электродов |
| `run_trkg4_fast_cem_refine()` | Точное CEM-уточнение кандидатов, отобранных сканом |
| `check_trkg4_patch_overlap_v5()` | Проверка инварианта непересечения патчей и измерение зазоров между ними |
| `trkg4_result_summary(result)` | Человекочитаемая сводка результата |

Порядок сохранения нескольких вариантов (`ttrkg_001.json`, `ttrkg_002.json`)
описан в [инструкции для пользователя](../Colab%20Notebooks/40.03_Инструкция_по_заданию_вариантов_электродов.md).
Сохранённые координаты требуют построения контактов и явного включения в расчёт;
HTML сам не запускает FEM.

Порядок важен: `run_trkg4_electrode_systems` строит общую сетку, на которую
опираются `run_trkg4_inverse_inhale` и далее `run_trkg4_fast_cem_refine`.

Перед расчётом раннер проверяет наличие обязательных STL, сетки и координат
электродов. Отсутствующий обязательный вход приводит к остановке с указанием
конкретного файла. Необязательная маска крови проверяется отдельно.

## Входные данные на одного испытуемого

В `data/<subject>/stl/`. Обязательная предобработка описана в
[`docs/CT_STL_MANDATORY_PREPROCESSING.md`](docs/CT_STL_MANDATORY_PREPROCESSING.md);
история версий поверхностей — в
[`docs/STL_SOLID_PREPARATION.md`](docs/STL_SOLID_PREPARATION.md).

| Файл для Nik | Роль |
|---|---|
| `body_solid_v3_1mm_r10_volume_fill.stl` | Внешняя замкнутая поверхность тела с руками, после заполнения полостей. Это то, что решается |
| `lungs_solid_v3_volume_fill.stl` | Заполненный лёгочный объём; `rho_lungs` — эффективное сопротивление «ткань + воздух» |
| `heart.stl` | Реальная единая маска сердца, не сфера. Миокард и кровь внутри неё отдельно не сегментированы |
| `bones.stl` | Замкнутая маска костей |
| `blood.stl` | Не является доступным входом для Nik; это только возможное будущее усложнение при появлении отдельной верифицированной маски |
| `body.stl`, `lungs_ct_full_clean.stl` | Исходные CT-поверхности, хранятся для прослеживаемости; в решении не участвуют |

Имена файлов задаются в `trkg4_subject_registry.m`, а не выводятся из
соглашения: `nik.stl.body` и `nik.stl.lungs` указывают на принятые solid-версии,
а исходники остаются под отдельными полями.

Отсутствующая необязательная маска — не безобидное событие: её объём сохраняет
проводимость фона и смещает расчётный `Z`. `validate_stl_inputs` сообщает об
этом отдельной строкой, а `assign_tissues_from_stl` — предупреждением.

Монтажи электродов — именованные CSV в `data/<subject>/electrodes/`, см.
[`docs/ELECTRODES_4.md`](docs/ELECTRODES_4.md). Единого
`electrodes_4_xyz_mm.csv` нет; по умолчанию используется монтаж «руки».
В каждом файле 4 центра в тех же миллиметрах и той же системе координат, что
STL, в порядке `I_plus`, `V_plus`, `V_minus`, `I_minus`.

Базовые координаты электродов не переносятся из STL-примера и должны быть
размечены для данной постановки. Кольцевой и широкий контакты рассматриваются
отдельно в параметрическом тесте `run_trkg4_arm_electrode_tests`. После
генерации сетки код сохраняет
`output/<subject>_electrode_diagnostics.csv` — расстояние от **запрошенного**
центра до ближайшей поверхности, сдвиг снаппинга, смещение центроида патча и
его площадь.

## Сетка

Расчёт идёт на заранее построенной проверенной сетке, а не на генерации «на
лету»:

```matlab
cfg.prebuilt_mesh_file = output/nik_body_solid_v3_1mm_local2mm_alg1.msh
```

Если файл задан, но отсутствует, расчёт **падает**. Молчаливый откат на
генерацию по `cfg.gmsh_mesh_size` (25 мм) подменял бы проверенную сетку 1 мм /
локально 2 мм и менял все импедансы без единого предупреждения. Пересобрать
сетку можно через `tools/gmsh_stl_to_msh_robust.py`; чтобы сознательно
вернуться к генерации из STL, нужно очистить `cfg.prebuilt_mesh_file`.

`cfg.mesh_target_size_mm` описывает характерный шаг решаемой сетки и должен
меняться вместе с `cfg.prebuilt_mesh_file`: от него зависят допуски диагностики
электродов.

Ранее принятая сетка воспроизводит фиксированные исторические монтажи, но не
поддерживает произвольное продольное перемещение малых электродов по рукам.
На длинных участках искусственных цилиндров отсутствуют промежуточные
поверхностные узлы, поэтому проекция нового центра может смещаться на десятки
миллиметров. Для параметрического монтажа требуется отдельная сетка с
локальным измельчением во всём исследуемом диапазоне положений. До её
прохождения через геометрический контроль численные значения такого теста не
используются как физический результат.

## Важный нюанс единиц

STL после CT почти всегда в миллиметрах, а проводимости задаются в `S/m`. Код:

1. строит mesh и выбирает tissue/electrode patches в миллиметрах;
2. перед `fwd_solve` масштабирует узлы модели в метры;
3. оставляет проводимости в `S/m` и контактный импеданс в `Ohm*m^2`.

Это нужно, чтобы абсолютный импеданс не уехал из-за несогласованных единиц.

## Инструменты подготовки геометрии

`tools/` содержит скрипты подготовки STL вне MATLAB: анализ и сравнение
поверхностей, заполнение полостей, воксельный remesh, децимация с сохранением
топологии, локальное измельчение под электродами, сборка сетки Gmsh. Точки
входа для Windows: `prepare_ct_stl_mandatory.ps1` — текущая обязательная
процедура, а `prepare_solid_stl.ps1` — более ранняя вспомогательная схема
voxel-remesh/split, которую нельзя подменять текущей процедурой без отдельного QC.
