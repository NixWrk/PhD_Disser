## Повторная сборка

Новая сборка требует отдельной рабочей редакции: сначала сохранить авторский
Word и назначить новый выходной файл. Текущие программы используют постоянное
имя результата и могут перезаписать его. При фиксации в Git повторная сборка
не выполнялась.

1. Проверить исходный Word и его хэш; сопоставить последующие авторские
   изменения с `drafts/`. Не восстанавливать текст из ранней версии автоматически.
2. Проверить пути изображений и зависимостей. Нужны Python с `python-docx`
   и `lxml`, Pandoc, а для обновления полей и точного отображения — Microsoft
   Word под Windows. Для растровой проверки использовался `pypdfium2`.
   В `tools/build_review.py` сохранён локальный путь Pandoc; часть реестров
   также содержит абсолютные пути прежней машины. Перенос в другую среду
   требует их проверки и перенастройки.
3. `tools/build_review.py` собирает Markdown и Word, используя также
   `../revision_20261028/tools/build_word.py` для стилей. Режим
   `--assemble-only` обновляет собранный текст и реестр, но не создаёт Word.
4. `tools/render_word.ps1` обновляет поля и экспортирует PDF. Обновление
   оглавления и ссылок выполнять при выключенном Track Changes; после
   обновления включать регистрацию исправлений для автора. Иначе техническое
   обновление полей может попасть в документ как редакторская правка.
5. Выполнить `tools/check_final.py`, сверить научное содержание и просмотреть
   страницы. Затем обновить аудит и комплект материалов. Скрипт
   `tools/finalize_local_audit.py` использует результаты визуальной проверки;
   не переносить старый положительный результат на новый Word.

`tools/apply_local_edits.py` сохраняет историю однократного применения правок
к предыдущей редакции. **Не запускать его поверх текущих или авторских
изменений:** он восстанавливает разделы из исходной версии. Для обычной
локальной правки редактировать нужные места и контролировать различия.

Повторять FEM-расчёты ради изменений терминологии или оформления не требуется.
Новая физическая постановка или изменение данных оформляются отдельным
расчётом с собственными входами, допущениями и проверками.
