# MATLAB_TRKG4_real_subjects — единый MATLAB/Python-pipeline моделей

> **Статус на 31.08.2026:** это единственная активная папка моделирования.
> Подтверждённые расчёты выполняются MATLAB/EIDORS/Gmsh и Python-скриптами.
> Исторический прототип перенесён в `archive/` и не является параллельным
> источником актуальных результатов.

Папка содержит прототип расчётов TRKG4 в MATLAB/EIDORS на анатомии реального
испытуемого. При этом чистый checkout не является самодостаточным: часть
принятых STL, prebuilt mesh и экспериментальные входы находятся вне Git.
Отдельной blood-маски для Nik нет по составу исходной сегментации: доступна
единая маска сердца. Документация трактует найденную точку как
регуляризованный локальный кандидат, а не доказанное уникальное решение.

До научного использования конкретного результата необходимо подтвердить
происхождение геометрии Inobitec, монтаж электродов, единицы, проводимости,
сетку, входной сигнал, параметры оптимизации, commit SHA и QC.

Полный отчёт: [AUDIT_2026-08-23.md](AUDIT_2026-08-23.md).

- `KALMYKOV_DICOM_DIR` — необязательный путь к индивидуальной DICOM-серии,

  копируются;
- `BLENDER_EXE` — необязательный полный путь к Blender для старых операций
  подготовки и визуального QC STL. Если переменная не задана, PowerShell-

пути текущего процесса MATLAB. Если зависимость отсутствует, расчёт
останавливается с явным сообщением. Модульная проверка запускается командой

```matlab
addpath('src');
results = runtests('tests');
assertSuccess(results);
```

После установки все восемь модульных тестов параметрического монтажа прошли
успешно. Для принятой сетки дополнительно выполнен полный профиль из 16
сценариев: четыре модели контакта при четырёх сочетаниях расстояний. К диску,
кольцу и широкой манжете добавлена идеализированная внутренняя поверхность,
совпадающая с поперечным сечением руки. Все сценарии прошли контроль

техническую работоспособность постановки, но не заменяют её физическую и

# MATLAB_TRKG4_real_subjects

Цель папки — выполнять MATLAB/EIDORS-расчёты на реальных CT/STL-данных
испытуемых и формировать проверяемые артефакты для notebook-отчётов.

Активная постановка:

- расчёт идёт в MATLAB/EIDORS/Gmsh; Python используется для подготовки,
  проверки геометрии и оформления отчётов;
- геометрия берется из CT/STL испытуемого;
- текущий принятый прямой FEM-прогон использует четырёхэлектродный монтаж
  ТТРКГ на руках; это ограничение конкретного прогона, а не метода ТТРКГ или
  инструмента выбора поверхностных координат;
- сердце не аппроксимируется сферой;
- радиус сердца не меняется;
- мягкие ткани идут как фон, легкие/сердце/кости назначаются по STL-маскам;
- результатом является статический transfer impedance для заданной реальной
  расстановки 4 электродов.

## Что взято из STL-примера

Из `archive/MATLAB_investigation_NIX/ForwardSolutionWithStlGeometryExample(by_NIX)`
перенесены и затем проверены MATLAB-хелперы в `vendor_stl_eidors/`:

- назначение тканей по закрытым STL-маскам;
- проверка попадания точек внутрь STL;
- выбор граничных треугольников электрода по площади;
- диагностика того, куда фактически попал каждый электрод на поверхности;
- ITIS-проводимости;
- служебные функции для centroids/cache/parallel.

Большие STL, output, Gmsh и вложенный `.git` не копировались.

## Точки входа

```matlab
addpath('src')
```

| Скрипт | Что делает |
|---|---|
| `run_trkg4_forward_subject('nik')` | Один прямой расчёт на монтаже по умолчанию (руки). Простейшая проверка, что вход и сетка на месте |
| `run_trkg4_arm_electrode_tests()` | Параметрически задаёт внутренние и внешние электроды на руках, сравнивает 5-мм диски, 5-мм кольца, широкие манжеты и идеализированные внутренние поперечные поверхности, а также проверяет теорему взаимности на одной сетке и одном назначении тканей |
| `run_trkg4_surface_coordinate_validation()` | Проверяет прототип задания центров по расстоянию вдоль поверхности и сравнивает его с действующей осевой схемой без повторного FEM-расчёта; постановка и текущий отрицательный результат переноса начала отсчёта описаны в `docs/SURFACE_ELECTRODE_COORDINATES.md` |
| `run_trkg4_electrode_systems()` | Сравнение трёх монтажей на **одной** сетке и одном назначении тканей, поэтому разница в `Z` вызвана только расстановкой. Пишет общую сетку в `output/nik_trkg4_<system>_full_v5_1mm_local2mm.mat` |
| `run_trkg4_inverse_inhale()` | Совместная подгонка `rho_soft`, `rho_lung` и позы решётки под многоразмерный эксперимент на вдохе |
| `run_trkg4_fast_pem_scan()` | Быстрый скан позы в приближении точечных электродов |
| `run_trkg4_fast_cem_refine()` | Точное CEM-уточнение кандидатов, отобранных сканом |
| `check_trkg4_patch_overlap_v5()` | Проверка инварианта непересечения патчей и измерение зазоров между ними |
| `trkg4_result_summary(result)` | Человекочитаемая сводка результата |

Ручное задание центров и направляющих выполняется автономным инструментом
`tools/build_surface_landmark_picker.py`. Он предназначен для
четырёхэлектродного монтажа ТТРКГ на любых требуемых участках внешней
поверхности тела и не применяется к боковым сборкам мягких тканей, РЕО32 или
стандартной ТРКГ. Подготовленный интерактивный файл находится в
`output/nik_surface_landmark_picker.html`. Общее задание координат и его
ограничения описаны в ноутбуке
`Colab Notebooks/40.03_Поверхностные_координаты_электродов_ТТРКГ.ipynb`.
Ноутбук `40.02` отвечает только за испытанный монтаж на руках и проверку
взаимности.
Порядок сохранения нескольких вариантов (`ttrkg_001.json`, `ttrkg_002.json`)
описан в [инструкции для пользователя](../Colab%20Notebooks/40.03_Инструкция_по_заданию_вариантов_электродов.md).
Сохранённые координаты требуют построения контактов и явного включения в расчёт;
HTML сам не запускает FEM.

Режим «Симметрично — 2 щелчка» подсвечивает выбранную и ответную позиции
при наведении мыши. Первый щелчок фиксирует I+/I−, второй — V+/V−.
Отражение выполняется относительно настраиваемой плоскости, ответная точка
проецируется на наружную поверхность; JSON сохраняет четыре явных центра.
Начальная плоскость по середине габаритов X является геометрическим допущением.

Основной режим позволяет последовательно выбрать на внешней поверхности четыре
именованных центра в порядке `I_plus`, `V_plus`, `V_minus`,
`I_minus`. Дополнительный режим «Расставить симметрично» использует два
независимых поверхностных пути для сторон I+/V+ и I-/V-. Первая точка каждого
пути служит выбранным анатомическим ориентиром. К путям применяются одинаковое
расстояние до внутреннего электрода и одинаковое расстояние от внутреннего
электрода до внешнего. Координаты не отражаются в глобальной системе. Поэтому
симметрия означает равенство заданных расстояний, а не зеркальное совпадение
анатомии. Для исследованного монтажа на руках опорной точкой может служить
граница «туловище–рука», но это частный вариант общей координатной схемы.

Интерфейс показывает непрозрачную освещённую поверхность тела и отдельно
управляемые слои скелета, лёгких и сердца. Он сохраняет обезличенный контракт
`trkg4_ttrkg_surface_v3`. MATLAB-функция
`trkg4_load_surface_landmarks` проверяет контракт. Свободно выбранные
центры передаются в существующий общий механизм проекции на поверхность.
Симметричные центры повторно вычисляются функцией
`trkg4_surface_montage_centres`. Функция
`trkg4_arm_surface_centres` сохранена для совместимости с частным
профилем на руках. Облегчение геометрии и параметры освещения применяются
только к отображению.

Порядок важен: `run_trkg4_electrode_systems` строит общую сетку, на которую
опираются `run_trkg4_inverse_inhale` и далее `run_trkg4_fast_cem_refine`.

Перед расчётом раннер проверяет наличие обязательных STL, сетки и координат
электродов. Отсутствующий обязательный вход приводит к остановке с указанием
конкретного файла. Необязательная маска крови проверяется отдельно.

## Входные данные на одного испытуемого

В `data/<subject>/stl/`. Обязательная предобработка описана в
[`docs/CT_STL_MANDATORY_PREPROCESSING.md`](docs/CT_STL_MANDATORY_PREPROCESSING.md);
история версий поверхностей — в
[`docs/STL_SOLID_PREPARATION.md`](docs/STL_SOLID_PREPARATION.md).

| Файл для Nik | Роль |
|---|---|
| `body_solid_v3_1mm_r10_volume_fill.stl` | Внешняя замкнутая поверхность тела с руками, после заполнения полостей. Это то, что решается |
| `lungs_solid_v3_volume_fill.stl` | Заполненный лёгочный объём; `rho_lungs` — эффективное сопротивление «ткань + воздух» |
| `heart.stl` | Реальная единая маска сердца, не сфера. Миокард и кровь внутри неё отдельно не сегментированы |
| `bones.stl` | Замкнутая маска костей |
| `blood.stl` | Не является доступным входом для Nik; это только возможное будущее усложнение при появлении отдельной верифицированной маски |
| `body.stl`, `lungs_ct_full_clean.stl` | Исходные CT-поверхности, хранятся для прослеживаемости; в решении не участвуют |

Имена файлов задаются в `trkg4_subject_registry.m`, а не выводятся из
соглашения: `nik.stl.body` и `nik.stl.lungs` указывают на принятые solid-версии,
а исходники остаются под отдельными полями.

Отсутствующая необязательная маска — не безобидное событие: область, которую
она должна была бы выделять, не получает отдельного тканевого класса. Её
проводимость определяется другими доступными масками и фоном, что может
смещать расчётный `Z` относительно модели с отдельным классом. Для Nix
отсутствие `blood.stl` означает, что кровь внутри единой маски сердца
относится к классу «сердце целиком». `validate_stl_inputs` сообщает об
отсутствии маски отдельной строкой, а `assign_tissues_from_stl` —
предупреждением.

Монтажи электродов — именованные CSV в `data/<subject>/electrodes/`, см.
[`docs/ELECTRODES_4.md`](docs/ELECTRODES_4.md). Единого
`electrodes_4_xyz_mm.csv` нет; по умолчанию используется монтаж «руки».
В каждом файле 4 центра в тех же миллиметрах и той же системе координат, что
STL, в порядке `I_plus`, `V_plus`, `V_minus`, `I_minus`.

Базовые координаты электродов не переносятся из STL-примера и должны быть
размечены для данной постановки. Кольцевой и широкий контакты рассматриваются
отдельно в параметрическом тесте `run_trkg4_arm_electrode_tests`. После
генерации сетки код сохраняет
`output/<subject>_electrode_diagnostics.csv` — расстояние от **запрошенного**
центра до ближайшей поверхности, сдвиг снаппинга, смещение центроида патча и
его площадь.

## Сетка

Расчёт идёт на заранее построенной проверенной сетке, а не на генерации «на
лету»:

```matlab
cfg.prebuilt_mesh_file = output/nik_body_solid_v3_1mm_local2mm_alg1.msh
```

Если файл задан, но отсутствует, расчёт **падает**. Молчаливый откат на
генерацию по `cfg.gmsh_mesh_size` (25 мм) подменял бы проверенную сетку 1 мм /
локально 2 мм и менял все импедансы без единого предупреждения. Пересобрать
сетку можно через `tools/gmsh_stl_to_msh_robust.py`; чтобы сознательно
вернуться к генерации из STL, нужно очистить `cfg.prebuilt_mesh_file`.

`cfg.mesh_target_size_mm` описывает характерный шаг решаемой сетки и должен
меняться вместе с `cfg.prebuilt_mesh_file`: от него зависят допуски диагностики
электродов.

Прежняя сетка воспроизводит фиксированные исторические монтажи, но не
поддерживает произвольное продольное перемещение малых электродов по рукам.
Для параметрического профиля принята отдельная сетка
`output/accepted_arm_parameter_mesh.msh` с целевым шагом 1 мм в рабочих
объёмах обеих рук. Она не заменяет сетку по умолчанию и передаётся в профиль
явно через `ArmPrebuiltMeshFile`.

Подготовка поверхности, сравнительный контроль качества 4 358 825
тетраэдров, фактическая геометрия 64 электродов и проверка взаимности описаны в
[`docs/ARM_PARAMETER_MESH_ACCEPTANCE.md`](docs/ARM_PARAMETER_MESH_ACCEPTANCE.md).
Приёмка относится к технической пригодности сетки для методических FEM-
расчётов и не является физической или экспериментальной валидацией модели.

## Важный нюанс единиц

STL после CT почти всегда в миллиметрах, а проводимости задаются в `S/m`. Код:

1. строит mesh и выбирает tissue/electrode patches в миллиметрах;
2. перед `fwd_solve` масштабирует узлы модели в метры;
3. оставляет проводимости в `S/m` и контактный импеданс в `Ohm*m^2`.

Это нужно, чтобы абсолютный импеданс не уехал из-за несогласованных единиц.

## Инструменты подготовки геометрии

`tools/` содержит скрипты подготовки STL вне MATLAB: анализ и сравнение
поверхностей, заполнение полостей, воксельный remesh, децимация с сохранением
топологии, локальное измельчение под электродами, сборка сетки Gmsh. Точки
входа для Windows: `prepare_ct_stl_mandatory.ps1` — текущая обязательная
процедура, а `prepare_solid_stl.ps1` — более ранняя вспомогательная схема
voxel-remesh/split, которую нельзя подменять текущей процедурой без отдельного QC.

## Проверка переносимости на геометрию Georg

Профиль `georg` служит независимой проверкой того, что подготовка геометрии,
параметрическое размещение электродов и MATLAB/EIDORS-расчёт не зависят от
файлов и координат Nix. Исходные и производные STL, сетки и результаты
остаются локальными. Их состав и ограничения описаны в
[`data/georg/README.md`](data/georg/README.md).

Подготовка выполняется последовательностью:

1. `tools/solid_fill_stl.py` устраняет внутренние полости и топологические
   тоннели исходной поверхности тела;
2. `tools/add_arm_extensions.py` строит два искусственных продолжения рук и
   записывает их центры, радиусы, длину, перекрытие и контрольные хэши;
3. `tools/prepare_arm_parameter_surface.py` создаёт поверхность с шагом около
   1 мм в рабочих областях электродов;
4. `tools/gmsh_arm_parameter_mesh.py` строит отдельную объёмную сетку Georg;
5. `tools/check_msh_quality.py` проверяет объём, ориентацию и вырожденность
   тетраэдров;
6. `run_trkg4_arm_electrode_tests('SubjectId', 'georg')` вычисляет прямой и
   взаимный передаточные импедансы для четырёх моделей контакта;
7. `tools/build_arm_electrode_report.py` объединяет геометрию, электроды,
   результаты и ограничения в автономном интерактивном HTML-отчёте.

Конфигурация `trkg4_config('georg')` выбирает только STL, сетку и кэш Georg.
Подстановка сетки Nix для этого профиля исключена. В первом проверочном
расчёте сопротивления мягких тканей и лёгких намеренно перенесены из профиля
Nix; поэтому результат характеризует переносимость геометрического и
вычислительного контура, но не индивидуальные параметры тканей Georg.

Автономный отчёт создаётся скриптом
`tools/build_arm_electrode_report.py`. Он показывает освещённую поверхность
тела, независимо управляемые слои костей, лёгких и сердца, положение
электродов, рассчитанные импедансы и ошибки взаимности. Этот HTML хранится в
`output/` и не копируется в notebook-файлы.

## Проверка переносимости на геометрию Yaroslav

Профиль `yaroslav` повторяет тот же вычислительный контур на третьей геометрии.
В отличие от профиля Georg, в принятом ручном наборе Yaroslav имеется маска
полости крови, но нет отдельно принятой маски миокарда или сердца целиком.
Искусственные продолжения рук имеют модельный диаметр 150 мм; этот размер не
является антропометрическим измерением испытуемого.

Для профиля используется смешанное разрешение сетки: 1 мм в тонких областях
четырёх электродных плоскостей, 5 мм в остальной части искусственных рук и
12 мм в туловище. Принятая очищенная сетка сохраняет полный объём поверхности,
не содержит отрицательных или вырожденных тетраэдров и читается EIDORS в
формате MSH 2.2. Состав исходных поверхностей, электрические параметры,
результаты четырёх моделей контакта и ограничения приведены в
[`data/yaroslav/README.md`](data/yaroslav/README.md).

Автономный интерактивный отчёт сохраняется в
`output/yaroslav_arm_electrode_portability_report.html`. Как и отчёт Georg,
он показывает по четыре электрода только для выбранного варианта контакта.

## Чувствительность целых компартментов и серия TEPC

Методика сравнения электродных сборок зафиксирована в
[ноутбуке 40.08](../Colab%20Notebooks/40.08_Сходимость_чувствительности_по_удельному_сопротивлению.ipynb)
и его [HTML-версии](../Colab%20Notebooks/40.08_Сходимость_чувствительности_по_удельному_сопротивлению.html).
Удельное сопротивление изменяется равномерно во всём компартменте при полном
переборе литературных диапазонов мягких тканей, эффективной сердечной области
и лёгких. Сравниваются два самостоятельных показателя: абсолютное
масштабированное влияние \(B=|\partial Z/\partial\rho|\Delta\rho\) и
избирательность \(Q=B/\sum B\).

На фиксированной модели Nix расчёт 16 параметрических сборок выделил следующие
рабочие кандидаты:

- мягкие ткани — № 15, четыре диска диаметром 5 мм при \(d=40\) мм и
  \(l=80\) мм;
- сердечная область — № 3 и № 7, четыре диска диаметром 5 мм при \(d=20\) мм
  и \(l=100\) или 80 мм;
- лёгкие по абсолютному влиянию \(B\) — № 3 и № 7;
- лёгкие по избирательности \(Q\) — № 4 и № 8, манжеты шириной 15 мм при
  \(d=20\) мм и \(l=100\) или 80 мм.

Эти варианты являются кандидатами для следующей проверки. Разброс
сердечного \(B\) между сборками составил 0,047 %, лёгочного — 0,163 %.
Пятиуровневая сетка по \(\rho\) достаточна для оценки каждой сборки отдельно,
но часть парных разностей сердца и лёгких требует дополнительного уточнения.
Клиническая оптимальность, влияние ошибки установки, контактного импеданса и
межиндивидуальной анатомии не проверены.

Серия [40.09](../Colab%20Notebooks/40.09_Подготовка_чувствительности_сборок_TEPC.ipynb)
переносит эту методику на пользовательские JSON сборок TEPC-2…TEPC-7.
Для всех четырёх ролей I+, V+, V− и I− приняты поверхностные диски диаметром
5 мм. После согласованного локального уточнения расчётной сетки все шесть
монтажей прошли геометрический контроль. Расчёт выполняется при 50 кГц по
профилю \(\rho\) этапа 40.08; статья использует 100 кГц, поэтому серия
проверяет переданные координаты в действующей модели и не воспроизводит
опубликованный эксперимент.

Запечатанный план содержит 78 контрольных состояний для проверки производных
и 1134 состояния полного перебора. Из корня `MATLAB_TRKG4_real_subjects`
последовательно выполняются:

```text
python tools/run_surface_sensitivity.py --base output/exploratory/tepc_preparation_20260911 --deps output/exploratory/arm_sigma_20260908/python_solver_deps --check
python tools/run_surface_sensitivity.py --base output/exploratory/tepc_preparation_20260911 --deps output/exploratory/arm_sigma_20260908/python_solver_deps --matlab <MATLAB_EXE> --pilot
python tools/run_surface_sensitivity.py --base output/exploratory/tepc_preparation_20260911 --deps output/exploratory/arm_sigma_20260908/python_solver_deps --matlab <MATLAB_EXE> --full
python tools/run_surface_sensitivity.py --base output/exploratory/tepc_preparation_20260911 --deps output/exploratory/arm_sigma_20260908/python_solver_deps --analyze
python tools/build_surface_sensitivity_report.py --base output/exploratory/tepc_preparation_20260911
```

Полный TEPC-расчёт завершён 14.09.2026: контрольная серия включает 78 состояний, основная матрица — 1134 состояния. Геометрическая и матричная подготовка прошла; предпочтительные множества и минимальные показатели устойчивы при переходе от трёх к пяти уровням $\rho$ и после добавления промежуточных состояний. Вместе с тем проверка интерполяции производных и $Q$, точности попарных разностей и знаков части парных предпочтений не прошла заданные критерии. Поэтому покрытие диапазона $\rho$ пока не признано достаточным для окончательного различения близких сборок.

На проверенном конечном наборе состояний предварительными лидерами являются TEPC-2 для мягких тканей по $B$ и $Q$, TEPC-4 для сердечной области по $B$, TEPC-7 для сердечной области по $Q$, TEPC-2 для лёгких по $B$ и TEPC-7 для лёгких по $Q$. Это результаты математической модели. Они сохраняются как кандидаты для дальнейшего сгущения параметрической сетки и проверки численной неопределённости.

Текущий статус расчёта хранится локально в `output/exploratory/tepc_preparation_20260911/orchestrator_status.json`, а машинно читаемый итог — в `analysis/summary.json`. Контракт и правила возобновления приведены в [описании расчётного контура](docs/SURFACE_SENSITIVITY.md).

Две обязательные проверки зафиксированы отдельно в [плане численной и физической валидации TEPC](docs/TEPC_VALIDATION_PLAN.md). Пространственная сходимость проверяет устойчивость $Z$, $S$, $B$, $Q$ и ранжирования при изменении FEM-сетки. Физическая валидация сопоставляет расчёт с независимыми измерениями прибора и многокомпартментного фантома. Воксель КТ 1 мм не заменяет ни одну из них: он задаёт шаг изображения, но не размер и качество всех тетраэдров, точность контактной аппроксимации или согласие с физическим объектом.
