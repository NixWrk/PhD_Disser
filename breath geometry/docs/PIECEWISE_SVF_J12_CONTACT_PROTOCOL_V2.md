# J1.2 v2: контактно-согласованный synthetic protocol

## Назначение

Этот протокол заменяет development/challenge v1 до запуска оптимизатора. Причина
замены зафиксирована в D-033: старый `SlidingPhantom` обеспечивал лишь равенство
нормальных компонент в исходных точках, но два его поля не отображали плевральную
границу в одну общую поверхность.

J1.2 v2 проверяет более узкий и корректный вопрос: может ли
`joint-piecewise-svf-torch-v0` восстановить по двум изображениям два региональных
SVF, которые сохраняют контакт на криволинейной границе и допускают скачок
касательного движения.

## Замороженные входы

- development:
  `configs/piecewise_svf_j12_contact_development_suite_v2.json`;
- held-out challenge:
  `configs/piecewise_svf_j12_contact_challenge_suite_v2.json`;
- конечный поиск:
  `configs/piecewise_svf_j12_contact_development_search_v2.json`.

Challenge-конфиг хранится в Git ради checksum, но его cases нельзя загружать,
генерировать или исполнять до фиксации единственного candidate отдельным
коммитом. Старые v1-конфиги остаются воспроизводимым отрицательным контролем.

## Конструктивный инвариант контакта

Исходная граница лёгкого — осесимметричный эллипсоид с `r_x = r_y`. Для обоих
регионов задаются:

1. одинаковые логарифмические масштабы `(a, a, c)`;
2. разные вращательные компоненты вокруг оси Z:
   - постоянная угловая скорость; или
   - угловая скорость, линейная по Z.

Поток каждого SVF меняет радиус в плоскости XY на `exp(a)`, координату Z на
`exp(c)` и независимо переставляет точки по азимуту. Поэтому оба потока
отображают исходный эллипсоид в одно и то же множество:

~~~text
(x / (r_x exp(a)))² + (y / (r_y exp(a)))²
  + (z / (r_z exp(c)))² = 1
~~~

Разница углов задаёт касательное скольжение. Равенство фиксированных нормальных
компонент остаётся только legacy-диагностикой и не используется как
доказательство контакта.

## Синтез пары

- Направление truth: `fixed-expiration_to_moving-inspiration`.
- Координаты массивов: XYZ, физические компоненты RAS+, миллиметры, локальное
  начало координат в voxel `(0, 0, 0)`.
- Lung/body velocity экспонируются независимо через общий проверенный
  scaling-and-squaring.
- Обратные поля получаются экспонентой отрицательных velocity, а не сменой знака
  готового displacement.
- Moving image собирается кусочно: значения лёгкого переносятся обратным lung
  field, значения стенки — обратным body field.
- Moving lung mask задаёт растр общей аналитической target-поверхности.
- Оптимизатор получает только изображения, маски и spacing. Параметры генератора,
  velocity/displacement truth и аналитическая поверхность ему недоступны.

## Обязательный preflight до GPU

Для каждого development case собственная truth должна пройти одновременно:

- analytic target-surface absolute p95 `≤ 0.05 мм`;
- analytic target-surface coverage в пределах `0.05 мм` `≥ 0.99`;
- raster target-surface p95 `≤ 0.75 мм`;
- raster coverage в пределах `0.75 мм` `≥ 0.95`;
- round-trip p95 для обоих регионов `≤ 0.05 мм`;
- региональный Jacobian p01 `≥ 0.2`;
- доля `J≤0` строго `0`;
- медианное касательное скольжение `≥ 0.5 мм`.

Если хотя бы один case не проходит, `optimizer_started=false`; пороги не
ослабляются, а причина записывается в batch manifest и notebook.

## Development и challenge gate

После exact-truth PASS выполняются ровно три заранее записанных варианта
`balanced`, `contact_strong`, `smooth_strong`. Все три development cases должны
пройти прежний полевой gate J1.2:

- lung/body endpoint p95 `≤ 1.5 × max(spacing)`;
- legacy fixed-normal mismatch p95 `≤ 0.75 мм`;
- ошибка медианного касательного скольжения `≤ 1.0 мм`;
- региональный Jacobian p01 `≥ 0.2`, `J≤0` строго `0`;
- raster target-surface p95 `≤ 0.75 мм`, coverage `≥ 0.95`.

Правила выбора и tie-break не изменены. После фиксации candidate challenge
исполняется один раз и требует PASS 2/2 без изменения кода или параметров.

Даже успешный synthetic challenge не разрешает парные измерения у людей. Он
разрешает только переход к J1.3 — независимой проверке correspondences на
реальной размеченной паре.
