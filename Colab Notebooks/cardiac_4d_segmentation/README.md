## Текущий результат и его статус

Главная цель — уточнение ударного объёма (УО) и фракции выброса (ФВ).
В 21.03 сохранены экстремумы доступных масок и отдельные условные оценки
периодического цикла. Модель применяется к Adam и Nix при допущении
сопоставимости сокращений; короткий и длинный R–R Georg анализируются
раздельно. Эти результаты относятся к разработке методики; независимая
точность сегментации, выбор конечных состояний и точность УО/ФВ не установлены.

По последнему решению автора новые ручные маски не ожидаются из-за
недостаточного контраста. Работа продолжается на исходных масках
TotalSegmentator. Остаточный контраст был у Georg, но это не обеспечило
пригодный новый ручной референс. Ручная анатомия Inobitec сохраняет свою роль
в проекте и не подставлена в данный покадровый расчёт.

| Раздел 21.03 | Что выполнено | Ограничение вывода |
|---|---|---|
| УО/ФВ и чувствительность | Выбор экстремумов, периодическая модель, сценарии изменения объёма и сетка параметров модели | Сценарии не являются принятыми анатомическими поправками; разброс не является доверительным интервалом |
| Совместная динамика ЛЖ/ПЖ | Нормированный объём, V/A, площадь, удлинённость и средние межкадровые скорости; 33 пары кадров | Все признаки получены из одних автоматических масок и не служат независимыми референсами |
| Локализация изменений | 18 пространственных сравнений на девяти интервалах | Совмещение не выполнялось; движение и ошибка сегментации не разделены; малое изменение объёма не устанавливает механическую фазу |

Индексация использует локально заданные рост и массу; возраст и пол выбирают
референсную группу. Сейчас антропометрия есть только для Nix и происходит
из авторского сообщения в выписке диалога. Её применимость к дате КТ —
допущение. Для Adam и Georg значения не заимствуются. Внесены МРТ-референсы
для мужчин 20–29 лет; автоматического переноса на другой пол или возраст нет.
Полные формулы, источники, расчёт и ограничения находятся в самом ноутбуке.
Приближение к референсному среднему и равенство УО желудочков не являются
критериями исправления масок.

## Как обновлять 21.03

Команды выполняются из `Colab Notebooks/cardiac_4d_segmentation` в окружении
с `requirements-base.txt` и `requirements-visualization.txt`.

**Обновить отчёт из сохранённых расчётов:**

```powershell
python build_cardiac_function_report.py --presentation-only
```

Режим проверяет прежние манифесты и контрольные суммы, читает сохранённые
объёмы и геометрию, обновляет представления и отдельно вычисляет BSA-индексы.
Он не запускает сегментацию и не пересчитывает исходные УО/ФВ или пространственные
разности. Для него нужны локальные кэши и результаты `function_analysis`,
включая зависимости совместного отчёта. При их отсутствии или несовпадении
контрольных сумм сборка останавливается; одной копии из Git недостаточно.
Файл `reference_indexing/anthropometry.local.json` необязателен: без него
индексы не рассчитываются. Его формат приведён в
[описании локальных результатов](heart_rr_analysis/README.md).

**Пересчитать геометрию и блок функций из имеющихся масок:**

```powershell
python build_cardiac_function_report.py --derived-root '<DERIVED_ROOT>'
```

Этот режим требует исходной таблицы объёмов, внешних КТ/масок и сведений
об их происхождении. Он может повторно использовать проверенный кэш геометрии,
но не является режимом обновления одного оформления.
Полный RR-разбор с явными путями временных метаданных описан в
[карте серии](21.00_Карта_4D_сердца_и_RR.md).

**Экспортировать уже сохранённый notebook в HTML без нового расчёта:**

```powershell
python -m jupyter nbconvert --to html --TemplateExporter.exclude_input=True --TemplateExporter.exclude_input_prompt=True --TemplateExporter.exclude_output_prompt=True '21.03_Вычитание_крови_и_объёмы_камер_RR.ipynb'
```

**Проверить вычислительные модули:**

## Следующие проверки

Приоритет — обоснование конечных кадров и устойчивость условных УО/ФВ.
Пространственное совмещение и анализ остаточных различий остаются будущей
вычислительной проверкой с отдельным учётом интерполяции. Нужно также
уточнить происхождение антропометрии и сопоставимость правил контурирования.
Имеющихся данных недостаточно, чтобы определить анатомическую поправку
по нормальному диапазону или одной геометрической корреляции.

Разделы ниже сохраняют инструменты получения масок и протоколы независимой
валидации. Они описывают условия такой проверки при наличии референса;
подготовка новых ручных масок не является текущим планом или условием
продолжения описательного анализа 21.03.

## Что выделяется

- `whole_heart` — самостоятельная маска всего сердца из открытой задачи
  TotalSegmentator v2 `total/heart`; она не строится объединением других масок;
- `blood_pool` — объединение полостей левого/правого предсердий и желудочков;
  аорта и лёгочная артерия в него не включаются;
- `myocardium` — выходной класс `heart_myocardium` задачи
  `heartchambers_highres`; в текущем прогоне он представляет преимущественно
  миокард ЛЖ и перегородку и не считается маской полного миокарда всех камер;
- для каждой сердечной фазы сохраняются бинарные NIfTI, STL в координатах RAS
  и объёмы из воксельных масок.

STL используется для визуализации и FEM, но не для первичного расчёта объёма:
формат не хранит единицы и систему координат, а сглаживание поверхности меняет
объём. Источником количественных значений остаётся бинарная NIfTI-маска.

## Последовательность обработки

1. `inventory` читает только DICOM-заголовки и проверяет, какой тег действительно
   разбивает серию на полные 3D-фазы без повторяющихся срезов.
2. `convert` создаёт по одному HU-NIfTI на фазу с явным преобразованием DICOM LPS
   в NIfTI RAS+ и сохраняет хэшированные SOP UID.
3. `segment_totalseg_v2.py` запускает две модели TotalSegmentator 2.18.0:
   открытую `total/heart` для независимого `whole_heart` и лицензируемую
   академическую `heartchambers_highres` для камер и миокарда. Лицензионное
   значение читается из пользовательской конфигурации и не сохраняется в коде
   или манифестах.
4. `build_v2_cardiac_products.py` формирует три продукта, удаляет мелкие
   компоненты, исключает пересечение камер из миокарда, экспортирует STL и
   рассчитывает показатели межмодельного и временного контроля качества.
5. `summarize_v2_cohort_qc.py` объединяет результаты добровольцев в JSON и CSV.
6. После автоматического прогона обязательны визуальный просмотр всех фаз,
   исправление клапанных плоскостей/ушек/устьев сосудов и независимое сравнение
   хотя бы части фаз с ручной сегментацией Inobitec.

`segment_totalseg_v1.py` и команда `cardiac4d.py products` сохранены как
исторический исходный вариант v1 и не являются предпочтительным методом.

## Контроль качества и независимая валидация

- правильная фаза и полный охват сердца;
- сохранённая геометрия DICOM/NIfTI и отсутствие зеркального отражения;
- раздельная проверка ЛП, ЛЖ, ПП, ПЖ и миокарда на каждом срезе;
- единые анатомические правила отсечения аорты, лёгочной артерии, полых и
  лёгочных вен;
- отсутствие скачков объёма между соседними фазами, объясняемых только ошибкой
  сегментации;
- сравнение с ручным референсом по коэффициенту Dice, 95-му процентилю
  расстояния Хаусдорфа (Hausdorff95), средней симметричной поверхностной
  дистанции (ASSD), объёму и воспроизводимости конечно-диастолической и
  конечно-систолической фаз (ED/ES);
- фиксация эксперта, даты, версии маски и причины каждой ручной правки.

## Статическое контрастное КТ

Для исследования без сердечных фаз применяется тот же сегментационный блок,
но входной каталог содержит ровно один файл `phase_00.nii.gz`. Такой результат
нельзя интерпретировать как динамическую последовательность или использовать
для расчёта ED/ES, УО и ФВ.

Если полный DICOM-объём встроен в проект Inobitec SPJ, он извлекается с явным
номером предварительно инвентаризированной серии:

```powershell
python spj_static_series_to_nifti.py `
  --spj '<INPUT_SPJ>' --series-number '<SERIES_NUMBER>' `
  --output-dir '<RUN_DIR>\input'

python segment_totalseg_anatomy.py `
  --input '<RUN_DIR>\input\phase_00.nii.gz' `
  --output-dir '<RUN_DIR>\anatomy' --subject-id '<SUBJECT_ALIAS>' --gpu 0

python segment_totalseg_v2.py `
  --input-dir '<RUN_DIR>\input' --output-dir '<RUN_DIR>\cardiac_masks' `
  --phase-start 0 --phase-stop 1 --gpu 0

python build_v2_cardiac_products.py `
  --segmentation-dir '<RUN_DIR>\cardiac_masks' `
  --output-dir '<RUN_DIR>\cardiac_products' --phase-start 0 --phase-stop 1
```

`segment_totalseg_anatomy.py` сохраняет отдельные сырые классы и групповые
NIfTI/STL для костей, лёгких, тела, скелетных мышц и жира. Термин «в поле
сканирования» обязателен для тела, мышц и жира: это не оценка состава всего
тела. Сердечный блок создаёт независимое `whole_heart`, кровь четырёх камер и
модельный миокард с теми же ограничениями, что и для 4D-КТ.

Единый паспорт одного статического прогона формируется командой:

```powershell
python summarize_static_segmentation_qc.py `
  --run-dir '<RUN_DIR>' `
  --manual-stl-inventory '<RUN_DIR>\qc\manual_stl_inventory.json' `
  --output '<RUN_DIR>\qc\static_segmentation_qc.json'
```

Паспорт проверяет совпадение гридов, ненулевые маски, расположение продуктов
внутри автоматического контура тела и межмодельное согласие сердца. Если
добавлены ручные STL, их интегральные объёмы сравниваются только для
герметичных поверхностей и только как геометрический QC, а не как валидация.

## Независимая валидация анатомических масок

Отдельный [протокол 21.05](21.05_Валидация_анатомической_сегментации_сердца_4D_КТ.md)
не изменяет ноутбук 21.03 и его временные артефакты. Для него предусмотрены:

- `build_cardiac_validation_candidates.py` — сохраняет под разными именами
  raw `total/heart`, четыре raw-камеры, их blood union, raw/postprocessed
  `heart_myocardium` и геометрический остаток `total/heart − blood`; остаток
  не интерпретируется как миокард;
- `validate_manual_cardiac_masks.py` — рассчитывает объёмную ошибку, Dice,
  surface Dice, ASSD, HD95, меж-/внутриэкспертную воспроизводимость, STAPLE
  или adjudication и кластерный бутстрэп по `subject_id`;
- `manual_validation_manifest.example.json` — безопасный шаблон без реальных
  путей и масок. Его lock-флаги намеренно равны `false`, поэтому файл не
  является готовым запуском или результатом.

```powershell
python build_cardiac_validation_candidates.py `
  --segmentation-dir '<LOCAL_DERIVED_ROOT>\<SUBJECT_ID>\automatic_masks_v2' `
  --segmentation-manifest '<LOCAL_DERIVED_ROOT>\<SUBJECT_ID>\automatic_masks_v2\<EXACT_SEGMENTATION_MANIFEST>.json' `
  --ct-phase-dir '<LOCAL_DERIVED_ROOT>\<SUBJECT_ID>\phases' `
  --geometry-mm-confirmed `
  --output-dir '<LOCAL_DERIVED_ROOT>\<SUBJECT_ID>\validation_candidates'
```

Флаг `--geometry-mm-confirmed` допустим только для существующих NIfTI с
`spatial unit = unknown` после сверки с DICOM/conversion provenance. Новые
NIfTI конвертера записывают единицы `mm`. Ручной количественный референс должен
быть независимым NIfTI на исходной CT-grid; STL остаётся только геометрическим
QC. Маски и отчёты с медицинскими агрегатами хранятся во внешнем защищённом
каталоге и не коммитятся без отдельного решения.

Для сравнения нескольких явно именованных покамерных кандидатов с независимой
ручной маской предусмотрен `benchmark_blood_segmentation_candidates.py` и
шаблон `benchmark_blood_segmentation_manifest.example.json`. Манифест требует
заранее зафиксированный план и допуск surface Dice; результаты accuracy
сопровождаются provenance/hash и subject-cluster bootstrap. При отсутствии
`manual_reference` запускается только технический QC со статусом
`no_accuracy_inference`. Сначала используйте `--dry-run`, затем указывайте
внешний защищённый `--output-dir`; отчёты могут содержать производные
медицинские данные.

Для отдельного 12-фазного технического пилота кандидатов raw, removal-only
`conservative_cleanup` и двух режимов локального nnInteractive предусмотрены
`pilot_blood_segmentation_candidates.py` и шаблон
`pilot_blood_segmentation_manifest.example.json`. Локальный manifest с

морфологию, регистрацию, ресэмплинг, временное сглаживание или разрешение
перекрытий; `total/heart` используется только как QC-вариант.

## Подготовка покамерного QC крови в 4D-КТ

`prepare_blood_chamber_review.py` принимает явный упорядоченный
`blood_chamber_review_manifest.example.json`: для каждой фазы указываются CT,
raw-маски `LA/LV/RA/RV` из `heartchambers_highres` и, при наличии,
`total/heart`. Скрипт сохраняет исходные покамерные кандидаты и их union,
считает объёмы, компоненты, перекрытия, containment и изменения между
соседними фазами. Четырёхзначная карта `LA=1, LV=2, RA=3, RV=4` создаётся
только при отсутствии overlap; пересечение с `total/heart` выдаётся только как
QC-вариант и не заменяет raw blood candidate. Морфология, временное сглаживание
и автоматическое разрешение конфликтов запрещены.

После заполнения манифеста и фиксации плана (`analysis_plan_locked_before_review
= true`) сначала выполнить безопасный просмотр входов без записи:

```powershell
python prepare_blood_chamber_review.py `
  --manifest '<REVIEW_MANIFEST>' `
  --segmentation-manifest '<EXACT_SEGMENTATION_MANIFEST>.json' `
  --output-dir '<EXTERNAL_DERIVED_ROOT>\<SUBJECT_PSEUDONYM>\blood_review' `
  --dry-run
```

Затем повторить команду без `--dry-run`. `--output-dir` должен находиться вне
репозитория: результаты являются производными медицинскими данными. При
`spatial unit = unknown` разрешён только явно обоснованный флаг
`--geometry-mm-confirmed` после сверки с DICOM/conversion provenance. Отчёт и
очередь `blood_review_queue.csv` имеют статус QC/ручной проверки, а не
клинической валидации.

## Сравнение геометрических приближений сердца

Основная программа выбора физиологически осмысленного и электрически
достаточного приближения закреплена в [плане из шести этапов](../40.15_План_исполнения_сравнения_моделей_сердца.md).
Историческая ветка 21.08 дополняет её подготовкой к проверке сегментации.
Она не заменяет расчёты на готовых масках 21.03.

`run_reduced_heart_geometry.py` использует существующие маски 39 фаз и
сравнивает сферу, эллипсоид и индивидуальную опорную форму с изотропным
масштабированием и переносом. Расчёт выполняется для целого сердца,
объединённой области крови камер и четырёх камер раздельно. Опорная фаза
выбирается для каждого человека отдельно в каждом исходном R–R-интервале. Все кандидаты используют объём
и центр объёма целевой фазы; прогноз движения на этом этапе не выполняется.

Для повторения скопируйте `reduced_heart_geometry.example.json` в локальную
конфигурацию внутри исключённой из Git папки `results`, укажите корень
производных масок и новый каталог результатов. Команду выполняйте из
`Colab Notebooks/cardiac_4d_segmentation`:

```powershell
python run_reduced_heart_geometry.py --config 'results/reduced_heart_geometry.local.json'
```

Каталог результатов не должен существовать до запуска. Он содержит
`geometry_comparison.jsonl` с пофазной геометрией и перекрытием,
`input_provenance.local.json` с контрольными суммами входов и кода,
`summary.json` с описательными сводками и `run_status.json` с состоянием
расчёта. Объёмы всех шести областей сверяются с таблицей 21.03;
проверочный объём крови равен объёму целого сердца минус объём остатка
после вычитания крови плюс объём крови за пределами маски сердца. Маски не изменяются, сегментация не повторяется.

Сводки перекрытия исключают опорные фазы у всех кандидатов. Непрерывный
объём сохраняется по построению; остаточное различие дискретных объёмов
характеризует представление на воксельной сетке. Перекрытие вычисляется
на расширенной сетке без обрезания кандидата. Оно характеризует потерю
формы относительно автоматической маски, но не устанавливает анатомическую
точность или электрическую эквивалентность. Эти вопросы требуют следующих
этапов плана.

Выполненные сравнения собраны в [ноутбуке 40.16](../40.16_Геометрическое_сравнение_моделей_сердца.ipynb)
и [читательском HTML](../40.16_Геометрическое_сравнение_моделей_сердца.html).
Для 234 сочетаний фазы и области дополнительно рассчитаны поворот
индивидуальной формы и аффинное преобразование, параметры которого заданы
геометрическими моментами. Проверка временных зависимостей содержит
480 оценок исключённой промежуточной фазы и шесть пропущенных случаев
с недостаточным числом кадров. Это сравнение с автоматическими масками,
а независимая анатомическая и электрическая точность пока не установлена.

Дополнительные команды выполняются из этой папки. Пути результатов
выбираются явно; существующие выходы не перезаписываются:

```powershell
python run_affine_heart_geometry.py --config results/reduced_heart_geometry.local.json --baseline results/reduced_heart_geometry_20260914/exploratory/comparison_02 --output results/reduced_heart_geometry_20260914/exploratory/affine_02
python heart_temporal_models.py --records results/reduced_heart_geometry_20260914/exploratory/comparison_02/geometry_comparison.jsonl --output results/reduced_heart_geometry_20260914/exploratory/temporal_02/results.json
python build_heart_geometry_results.py
```

Последняя команда обновляет основной 40.16 из сохранённых результатов
`comparison_02`, `affine_01` и `temporal_01`; она не запускает сегментацию
или FEM. Каталоги `affine_02` и `temporal_02` в примерах выше предназначены
для отдельного повторения расчёта и автоматически в отчёт не включаются.

Для следующего электрического сравнения принято правило неподвижного фона:
исходное сердце заменяется мягкими тканями, лёгкие и кости сохраняются,
а каждый новый вариант сердца накладывается заново на этот фон. Освобождённые
участки возвращаются к фоновому материалу. Предварительная проверка на
статической FEM-сетке подготовила отдельные карты для исходной формы,
сферы и эллипсоида; все девять переходов восстановили фон корректно.
Это ещё не расчёт импеданса. Правило, численные результаты и ограничения
описаны в разделах 8–8.1 ноутбука 40.16.

разделения. Автоматическая маска является вычислительным ориентиром,
а не независимо проверенным ручным эталоном.

Итоговое проектное сравнение содержит 60 записей: 20 представлений и
критериев на трёх КТ-примерах, включая контрольную автоматическую маску
целевой фазы. Отдельно выполнены 27 MATLAB-расчётов: девять вариантов
на тех же трёх примерах с площадочной выборкой 32768 точек.

Для Г3а, Г3б, Г3в и Г5 выполнены 12 опорных расчётов с подгонкой по всем
точкам поверхности трёх примеров. Пофазное сравнение Г3в/Г5 содержит
78 расчётов на 39 фазах и остаётся приближённым: подгонка использует
выборку 4096 точек, а среднеквадратичное расстояние до поверхности (RMS)
оценивается по выборке 8192 точек. Шесть опорных фаз отделены от 33 остальных.
Полная подгонка существует только для трёх примеров. Эти результаты
не устанавливают глобальный оптимум, точность автоматических масок
или популяционную применимость.

`run_heart_method_comparison.py` обрабатывает одинаковые маски методами
проекта. Новые сферы реализованы в `heart_additional_sphere_methods.py`,
эллипсоиды — в `heart_additional_ellipsoid_methods.py`. Каждый результат
сохраняется отдельно; возобновление требует совпадения протокола,
кода и идентичности случая. Неудачные оптимизации сохраняют свой статус.
В новой согласованной серии сравнения сфер и эллипсоидов окончательная
RMS вычислена по полной поверхностной квадратуре, независимо от числа
точек подгонки. Для преобразованной индивидуальной маски аналитическая
метрика расстояния до эллипсоида неприменима и не подменяется нулём.
Полная сферическая подгонка выполняется отдельным скриптом
`heart_surface_full_reference.py`. Исходники новых серий сохранены перед
запуском в `source_used`; пилотные результаты и пофазный расчёт сохраняют
свои исходные версии кода и прежние правила оценки RMS.

Пример запуска из этой папки с уже подготовленной локальной конфигурацией:

```powershell
python -B run_heart_method_comparison.py --config results/reduced_heart_geometry_20260914/run_config.local.json --baseline results/reduced_heart_geometry_20260914/exploratory/comparison_02 --output results/reduced_heart_geometry_20260914/exploratory/new_method_comparison --methods T0,I1,G1,L1,G3c,G5 --fit-points 4096 --eval-points 8192
python -B build_heart_method_comparison_report.py
```

Вторая команда исполняет только представление сохранённых результатов.
Она не запускает повторно геометрическую подгонку или FEM. Для полного
повторения необходимо сначала выполнить требуемые расчётные наборы,
указанные в модуле `heart_method_comparison_report.py`.

Библиотеки MATLAB сохранены отдельно в
`MATLAB_TRKG4_real_subjects/vendor_heart_fits` с версиями, лицензиями и
контрольными суммами. Подготовка и проверка входов выполняется
`heart_library_fits.py`; MATLAB-батч — `run_heart_library_fits.m`.
Сходство результата не объединяет метод проекта с библиотечным вариантом.

В электрическом пилоте выполнены 18 сочетаний «исходная форма, сфера,
эллипсоид × TEPC-2–TEPC-7». Все материальные матрицы для новых геометрий
собраны заново. Контакты имеют диаметр 5 мм; физические параметры и
ограничения приведены в 40.17. Этот опыт не устанавливает чувствительность
к малому изменению объёма и координат.

Проверка 66 геометрических состояний выявила значимую ошибку производных
при назначении материалов по центрам тетраэдров. Код
`heart_fractional_materials.py` учитывает частичное заполнение граничных
элементов; выполнены 198 оценок на трёх уровнях интегрирования.
Уточнение интегрирования материала не заменяет пространственную сходимость
электрического решения. Выполнен дополнительный опыт из 13 решений для TEPC-2: производные
импеданса по объёму проверены при двух шагах и двух уровнях интегрирования.
Он описан в разделе 6.2 отчёта 40.17. Расширение на индивидуальную форму,
координаты и уточнённую сердечную FEM-сетку остаётся следующим этапом.
