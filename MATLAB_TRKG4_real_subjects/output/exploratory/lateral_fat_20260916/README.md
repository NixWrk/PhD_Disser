# Жир в прямой модели боковых сборок

Результат входит в раздел 5.5 [ноутбука 33.09](../../../../Colab%20Notebooks/33.09_Выбор_размеров_и_числа_боковых_сборок.ipynb). Рассчитываются все девять независимых размеров Ника, от 50 до 140 мм, при фиксированном положении C01. Размер 100 мм исключён по прежнему субъектному QC. Новая локализация и обратная задача здесь не выполняются.

Пять материалов: остаточный мягкотканный фон, лёгкое, кость, сердце и жир. Фон получает свойства мышцы; кость — кортикальной кости; вся область сердца — сердечной мышцы. Подкожный и внутренний жир объединены и получают одинаковые свойства Fat. Свойства заданы по [IT’IS V5.0](https://itis.swiss/virtual-population/tissue-properties/downloads/database-v5-0), DOI 10.13099/VIP21000-05-0, при 50 и 100 кГц. Используется действительная проводимость, контактное сопротивление фиксировано. Никакая подгонка сопротивлений к эксперименту не выполняется.

## Происхождение геометрии

Сохранённая автоматическая маска жира найдена, но относится к укороченной сердечной КТ и не покрывает верхний край длинной сборки. Поэтому на полной статической серии 301 повторно выполнены задачи total и tissue_types в TotalSegmentator 2.18.0. Версия, классы и хэши продуктов записаны в segmentation/segmentation.json; преобразование 241 DICOM-среза — в segmentation/conversion.json. Персональные DICOM-поля не включаются в отчёт.

Официальное описание задач и ссылка на публикацию: [TotalSegmentator](https://github.com/wasserth/TotalSegmentator#subtasks). Автоматические маски не являются независимо валидированной анатомией. Отдельная маска крови не вводится. Приоритет пересечений: лёгкое, кость, сердце, жир, фон. Текущая сетка наследует прежнюю внешнюю поверхность тела; новая автоматическая маска тела не используется для её перестроения.

Прежние FEM-узлы, тетраэдры, наружная граница и CEM-контакты сохранены. Каждый расчёт имеет четыре диска диаметром 5 мм; одновременно подключённый набор из всех размеров не моделируется. Контактное сопротивление равно 0,00015915494309189532 Ом·м². Нормировка тока 1 А вычисляет передаточное сопротивление и не означает ток реального прибора. RAS переводится в систему FEM стандартным обращением осей X и Y. Дополнительная регистрация или оптимизация положения не выполняется.

В элементах вне поля КТ, включая продолжения рук, сохранён мягкотканный фон. В plan.json отдельно указан объём элементов с центрами вне поля: около 952 мл, или 4,72% расчётного тела; это оценка по центрам элементов. Известная КТ задаёт геометрию вдоха для обоих табличных состояний лёгкого. Категория deflated лишь условно сопоставлена выдоху добровольца.

## Что сравнивается

Прежняя четырёхтканная модель из раздела 5.4 сопоставляется с двумя версиями новой разметки: жир со свойствами фона и жир с отдельной проводимостью. Их разность определяет эффект свойств жира. Разница новой версии без жира и прежней модели включает смену масок и способа их переноса; её нельзя считать измеренной ошибкой сегментации.

Для линейных тетраэдров интегрируется проводимость по объёмным долям материалов. Первое сравнение 256 и 1024 точек не прошло заранее выбранный численный порог 0,02 Ом + 0,001|Z|. Максимальное расхождение составило 0,230 Ом. Этот опыт сохранён в корне каталога. Уточнение до 4096 точек хранится в refined; первые 1024 точки и их доли воспроизведены точно. Совпадение интегрирования не доказывает пространственную сходимость FEM-сетки.

## Файлы результата

- refined/comparison.csv — прогнозы новой модели без жира и с жиром, эксперимент и прежний прогноз.
- refined/increments.csv — раздельные изменения от свойств жира и перехода к новым маскам.
- refined/metrics.csv — среднеквадратичные и относительные расхождения с наблюдениями.
- refined/quadrature_comparison.csv — разности между 1024 и 4096 точками.
- refined/comparison.html — интерактивный график с переключением 50/100 кГц.
- refined/plan.json, requests.csv, responses.csv, execution.json, qc.json — полный план, прямые ответы и проверки уточнённого опыта.
- mask_overlap.csv, mask_comparison.csv, geometry_qc.json — согласование масок и независимые математические тесты.
- segmentation_plane.png — диагностический срез в фактической плоскости текущей сборки; отдельная проверка переноса, не новый рисунок основного отчёта.
- initial_worker.m и initial_analysis.py сохраняют точные версии первого завершённого расчёта до уточнения.

КТ, NIfTI, MAT с сетками/долями/матрицами, локальная конфигурация и технический неудачный запуск остаются локальными. В Git сохраняются исполняемый код, отчёт, небольшие таблицы и контрольные суммы. Предварительный график не заменяет результат прошедшего проверку уточнения.

## Повторение

Рабочая папка — MATLAB_TRKG4_real_subjects. Локальный inputs.local.json содержит dicom_directory, series_number (301), output (каталог segmentation нового опыта) и gpu. Пути к исходным медицинским данным в переносимый код не входят. Для нового повтора использовать новый каталог; запечатанные планы не перезаписывать.

~~~text
python tools/lateral_fat_segmentation.py convert --config OUTPUT/inputs.local.json
PYTHON_WITH_TOTALSEG_V2 tools/lateral_fat_segmentation.py segment --config OUTPUT/inputs.local.json
python tools/lateral_fat_prepare.py --out OUTPUT
~~~

~~~matlab
run_pipeline('Profile','lateral_fat_forward','OutputDir','OUTPUT');
~~~

В текущей сохранённой реализации уточнение и построение отчёта используют каталог по умолчанию output/exploratory/lateral_fat_20260916. Для другого каталога необходимо явно изменить константу OUT в новом экземпляре подготовки и пересоздать план; команды не обещают автоматической переносимости всех путей.

~~~text
python tools/verify_lateral_fat.py geometry
python tools/lateral_fat_refine.py
~~~

~~~matlab
run_pipeline('Profile','lateral_fat_forward','OutputDir','output/exploratory/lateral_fat_20260916/refined');
~~~

~~~text
python tools/lateral_fat_analysis.py
python notebooks/build_lateral_array_design.py
python tools/verify_lateral_fat.py visual
~~~

Для повторения первоначального отрицательного численного контроля сохранены его точные код и таблицы. Для нового запуска уточнения необходимо сохранить выполненный первоначальный решатель под именем initial_worker.m: его хэш входит в происхождение refined. Успех этой вычислительной проверки не является физической валидацией и не подтверждает истинные сопротивления добровольца.
