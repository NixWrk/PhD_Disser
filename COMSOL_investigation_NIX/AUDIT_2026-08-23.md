# Критический аудит — COMSOL_investigation_NIX

- Дата фиксации: 2026-08-23
- Исходная задача Codex: `01a02e78-2fb8-7192-ac0c-ebb671f35869`
- Режим: read-only; отдельная задача была технически прервана, поэтому итоговый
  проход завершён локально в каноническом checkout.
- Базовая ветка: `Калмыков`.

## Итог

`COMSOL_investigation_NIX` — исторический набор проб COMSOL 6.0, а не активная
или валидированная FEM-ветка. Этот статус подтверждён автором проекта. Папка
полезна как журнал постановок, вариантов электродов и диагностики API, но не
образует самодостаточный воспроизводимый расчёт.

## Критические проблемы

1. README описывает файлы и результаты, которых нет в отслеживаемом состоянии:
   `geometry/TTrans_for_NIX.step`, `models/`, `results/`, `logs/` и
   `results_summary.csv` отсутствуют в Git. STEP, основные модели, логи и
   ключевые CSV нельзя восстановить из чистого checkout.
2. Все runner-файлы привязаны к COMSOL 6.0, конкретной локальной установке и
   путям `C:\tmp`. Переносимого описания окружения, лицензии, версии модели и
   контрольных сумм внешних входов нет.
3. Нет manifest, связывающего ручную Inobitec-сегментацию, конкретную анатомию,
   расположение электродов, физиологическую запись и результат расчёта.
   Следовательно, сохранённые числа и изображения не подтверждают
   субъект-специфическую валидацию.
4. Исторические интерпретации зависят от предположений о приборе, электродной
   постановке и геометрическом коэффициенте. В README они уже названы
   гипотезами; прямой контрольный эксперимент и независимая валидация не
   зафиксированы.
5. В `homogeneous_electrode_study/` отслеживаются бинарные `.mph` и
   производные PNG/CSV. Они не имеют общего run manifest с SHA входа, параметрами,
   версией COMSOL и формальным QC; бинарную модель нельзя содержательно проверить
   обычным Git diff.

## Существенные проблемы

- `RUNBOOK_COMSOL_6_0.md`, Java-раннеры, MATLAB LiveLink-черновик и README
  содержат машинозависимые абсолютные пути.
- `.gitignore` исключает основные `.mph` и `.step`, но делает исключение
  для бинарных моделей однородной серии; политика хранения артефактов
  неоднородна.
- Java и MATLAB-файлы частично продублированы в `Colab Notebooks`, поэтому без
  явного канонического источника копии могут расходиться.
- В tracked-состоянии нет тестов, CI или автоматической проверки COMSOL API,
  выбора доменов, граничных условий, единиц и геометрии электродов.
- README содержит субъектно-связанные производные численные значения и
  интерпретации. Raw медицинские изображения не обнаружены, но перед внешней
  публикацией требуется privacy-review.

## Следующий безопасный шаг

Заморозить папку как историю и не продолжать расчёты на реальных данных.
Удаление бинарных моделей или санитарная очистка истории требуют отдельного
решения. Если отдельный алгоритм понадобится для TRKG4, переносить только
минимальный фрагмент в изолированной ветке после фиксации входов, единиц,
электродов, версии COMSOL и теста на обезличенной синтетической геометрии.
