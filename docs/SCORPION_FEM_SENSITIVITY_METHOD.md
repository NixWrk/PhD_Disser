# Чувствительность и локальная идентифицируемость Scorpion FEM

Статус: реализация этапа разработки методики. Численные результаты конкретного
участника появляются только после его завершённого `electrical/forward.local.json`.
Тесты на известных матрицах проверяют обработку, а не физиологию и не точность FEM.
Участники, КТ-фазы и дыхательные состояния анализируются отдельно.

## Входы и запуск

`base` — собственная локальная папка одного участника, созданная родителем.
В ней используются:

- `electrical/forward.local.json`: сохранённые прямые FEM и adjoint Jacobian;
- `electrical/prepared_materials.mat`: неизменные `parts(2,5)`, `mm`, `identity`;
- `cem/cem_contacts.mat` и `cem_contacts_manifest.local.json`: исходные конечные
  контакты, явные группы, происхождение и QC;
- исходный CEM input sidecar из `cem_contacts_manifest.local.json.input_json`;
- `materials/`, `reference_materials.local.json`, `configuration.local.json` и
  связанные паспорта; исходные геометрические паспорта не переписываются.

Постобработка baseline не загружает крупные MAT и не запускает решатель:

```powershell
python MATLAB_TRKG4_real_subjects/tools/scorpion_fem_sensitivity.py --model-root <base> --subject <georg|nik|yaroslav> --output-dir <fresh-output>
```

Выход — `sensitivity.local.json` в новом локальном исключённом каталоге на том же
диске исследовательской работы. Код переносим: абсолютные пути данных не встроены.
Программа не выбирает другого участника или старую модель при отсутствии входа.
Сохраняются SHA baseline и его идентификаторы; наличие вспомогательных MAT
отмечается отдельно. Для проверки контактов эти MAT уже обязательны и проверяются.
JSON не создаёт автоматически открытых читательских таблиц. Коммиты и публикация
данных не выполняются.

Поддерживаются контракты `scorpion_own_CT_forward_v1/v2` и совместимый по полям
`scorpion_smart_forward_v1`. Неизвестная схема требует явного адаптера.
В `answers` обязательны `state`, `rule`, `case_id`, `rho_ohm_m`,
`transfer_matrix_ohm`, `jacobian_logrho`, `ttrkg_Z_ohm`, `lateral_Z_ohm`.
MATLAB JSON сохраняет оси `J(4,4,4)`; порядок последней оси `[1,2,4,5]`.

## Что вычисляется

Порядок пяти материалов: мягкотканный фон, лёгкое, кость, всё сердце, жир.
Кость фиксирована; четыре столбца соответствуют фону, лёгкому, всему сердцу,
жиру. Сердце — эффективная единая область; кровь и миокард здесь не разделены.
Частота — 100 кГц. По подтверждению автора от 26.10.2026 каналы Scorpion
разделены по времени; собственное возбуждение `own_drive` соответствует
этому режиму. Сложение источников с относительной фазой не используется.

Из `T(2,1)` извлекается знаковый ТТРКГ, из `T(4,3)` — знаковый боковой
передаточный импеданс. Перекрёстные элементы `T` не добавляются как измеренные
наблюдения. Отдельные строки соответствуют собственным монтажам baseline.
Их совместная интерпретация предполагает общие сопротивления внутри одного
состояния; сопоставимость реальных последовательных записей этим не доказана.

Канонический `trkg4_lateral_cem_response` возвращает
`Jlog[i,j] = dZ[i]/dln(rho[j])`. Сохраняются три разные матрицы:

| Матрица | Определение | Единицы | Координаты возмущения |
|---|---|---|---|
| `dZ_drho` | `Jlog[:,j] / rho[j]` | 1/м | `delta rho`, Ом·м |
| `dZ_dlogrho` | исходный `Jlog` | Ом | `delta ln(rho)` |
| `dimensionless_signed_elasticity` | `Jlog[i,j] / Z[i]` | безразмерная | `delta ln(rho)` |

Последняя матрица описывает относительные изменения знакового Z. Деление на
`abs(Z)`, модули производных и подмена нуля малым числом не используются.
При нулевом Z нормированная матрица данного набора недоступна; исходные
производные остаются в результате. Нормирование не является отбеливанием
шума и не задаёт точность измерений.

Для боковых строк, ТТРКГ и совместного набора отдельно вычисляются SVD, ранг,
сингулярные числа, полный правый ортонормированный базис, нуль-пространство
и слабейшее направление. По умолчанию порог ранга равен
`max(m,n) * eps * sigma_max`; `--rank-rtol` задаёт явный иной относительный
порог, который записывается в результат. Это машинный алгебраический порог,
а не измеренная разрешающая способность эксперимента.
Числовые метаданные порога явно переводятся в Python `float`: на Windows
последовательность импорта геометрических зависимостей может оставить в кэше
NumPy `finfo(float64).eps` со скалярным типом `longdouble` при том же значении.
Это проверяется отдельным запуском Python после импорта `ct_fem_core`;
численный алгоритм ранга и физические процедуры не меняются.

Если строк меньше четырёх или ранг меньше четырёх, полная обусловленность
считается бесконечной: в строгом JSON хранится `null` вместе с
`condition_status=rank_deficient_infinite`. Конечное отношение сингулярных
чисел на различимом подпространстве хранится под отдельным именем и не
объявляется обусловленностью полной обратной задачи. Спектр пространства
четырёх параметров дополнен структурными нулями. Нуль-векторы показывают
локально неразличимые комбинации в координатах соответствующей матрицы;
слабейший правый вектор — наименее чувствительное направление. При кратных
сингулярных числах отдельные базисные векторы не уникальны. Локальный полный
ранг не доказывает глобальную единственность или практическую идентифицируемость.

## Численный контроль и границы вывода

Пары q1024/q4096 обязаны иметь одинаковые строки, сопротивления и состояние.
Завершённый ограниченный v2-отчёт с одним правилом также читается, но отсутствие
пары сохраняется как `not_run_both_rules`; он не подменяет полный цикл контроля.
Используется наибольшее фактически рассчитанное правило, записанное в анализе.
Сохраняются знаковые разности Z и Jacobian, спектральная норма разности,
её отношение к норме тонкого правила и SVD обоих правил. Число сингулярных
чисел выше наблюдаемой разности является описательным индикатором. Эта
разность не служит доказанной верхней границей полной численной ошибки,
дисперсией шума или проверкой сеточной сходимости.

`derivative_checks` baseline переносится целиком. Покрытие FD указывается
для фактически проверенных `case_id` и `state`; успешную проверку первого
монтажа на вдохе не распространяют на все остальные. Непроверенные случаи
отмечаются явно. Ошибки решателя и взаимность остаются в исходном baseline.
Флаг `baseline_reported_numerical_checks_passed` относится к опубликованным
baseline-проверкам, а `numerical_controls_complete` требует покрытие всех
анализируемых случаев и состояний FD и наличие обоих правил. Эти статусы
не означают сеточной или экспериментальной валидации.

КТ получена на глубоком вдохе с задержкой. `exhale` на неизменной КТ —
условный расчёт тканевых параметров, а не реальная анатомическая фаза выдоха.
Состояния не объединяются для искусственного увеличения ранга. Шумовая
дисперсия, доверительные интервалы и индивидуальная физиологическая точность
не задаются. Здесь не оцениваются УО/ФВ и не утверждается клиническая валидация.

## Ограниченная проверка размещения

Для каждого участника принят один монтаж `L140_TT2x2`. Передний/задний
сценарий задаётся смещением исходных FEM-центров всех четырёх боковых
контактов на `[0,+5,0]` либо `[0,-5,0]` мм в LPS с повторной проекцией на
ту же внешнюю FEM-поверхность. Это явное смещение перед проекцией, а не
заданная геодезическая длина. Реальные положения электродов этим не измерены;
±5 мм не является доверительным интервалом автора. ТТРКГ-контакты сохраняются.

```matlab
% Подготовка: без FEM-факторизации. Вызывать после готовности собственного CEM.
run_scorpion_contact_sensitivity('Action','prepare', ...
    'ModelRoot',base,'OutputDir',fresh_placement_prepared);

% Только родитель, после baseline, в согласованном единственном solver slot:
run_scorpion_contact_sensitivity('Action','solve', ...
    'ModelRoot',base,'PreparedDir',fresh_placement_prepared, ...
    'OutputDir',fresh_placement_solved,'SolverLockFile',shared_lock_file);
```

`prepare` сохраняет новые raw и projected центры, заданный и фактический сдвиг,
проекционное расстояние, нормальную и касательную составляющие относительно
исходной грани, исходные/новые попарные расстояния A–M–N–B и их разность.
Знак нормальной компоненты относится к записанной ориентации грани; наружная
ориентация отдельно этим анализом не доказывается.
Новый sidecar явно содержит `reconfiguration_provenance` и SHA исходных
контактных файлов, mesh и паспортов. `original_projected_lps_mm` сохраняет
исторический источник, `source_projected_lps_mm` задаёт новый сценарный центр.
Новые площадки создаёт только канонический `run_ct_fem_contacts_prepare`.

Площадь диска 5 мм, положительный SI контактный импеданс, физическое наличие
контактов, группировка и все прежние допуски сохраняются. Проверяются footprint,
индуцированные грани, связность, непересечение, площадь, центр и размер.
Дополнительно точное совпадение нового footprint со старым вызывает отказ:
изменение подписи старой площадки не является переносом. При невозможности
размещения сохраняется отказ в `contact_plan.local.json`; допуски не расширяются,
сетка автоматически не сгущается. Два сценария оцениваются независимо, но
`solve` требует успешной подготовки обоих.

`solve` использует неизменные собственные `parts(2,:)`, `mm` и вдоховые rho
из baseline. Сборка поля остаётся результатом канонического `system_mat_fields`
и `trkg4_scale_fmdl_to_si`; новая процедура её не дублирует. Ровно две новые
FEM-факторизации выполняются через `trkg4_lateral_cem_response` для новых CEM,
с Jacobian по тем же четырём rho. Файл общей блокировки по умолчанию совпадает
с `run_scorpion_session_fem`: относительный путь
`output/exploratory/scorpion_session_runtime_20261026/sparse_solver.lock` внутри
MATLAB-проекта. Родитель может передать согласованный `SolverLockFile`.
Занятый slot вызывает немедленный отказ до загрузки больших material matrices.
Сам факт наличия этой процедуры не означает выполненные расчёты.

После готовности `contact_sensitivity.local.json` его можно присоединить:

```powershell
python MATLAB_TRKG4_real_subjects/tools/scorpion_fem_sensitivity.py --model-root <base> --subject <subject> --placement-result <placement-solved/contact_sensitivity.local.json> --output-dir <fresh-output-with-placement>
```

Проверяются совпадение участника и SHA baseline; сохраняются знаковые изменения
Z и Jacobian. Два смещения не исчерпывают неопределённость позы, ориентации,
контактного импеданса, анатомии, прибора и состояния участника.

## Приёмка реализации

```powershell
python -m pytest tests/test_scorpion_fem_sensitivity.py -q -p no:cacheprovider --basetemp=<fresh-local-test-directory>
```

Тесты включают известные ранг/нуль-пространство, сохранение отрицательных
производных, цепное правило, нулевой Z, парность интеграционных правил,
локальность FD, раздельность состояний и участников, строгий JSON и запрет
перезаписи результатов. MATLAB проверяется `checkcode` без большого решателя.
На малой синтетической кубической сетке (9261 узел, 48000 тетраэдров)
фактически выполнен полный маршрут `prepare`: оба переноса прошли прежний
CEM QC и проверку нового footprint, а записанные нормальные/касательные
составляющие проверены. Это тест геометрической процедуры; куб не представляет
реальный монтаж 140 мм или анатомию участника. FEM-поле в этой проверке не решалось.
Завершение первого ограниченного цикла требует реальных baseline всех трёх
участников и фактического статуса обоих новых CEM/решений каждого участника.
