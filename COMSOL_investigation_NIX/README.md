# COMSOL investigation NIX

Папка фиксирует разбор модели `TTrans for NIX.step` и попытки понять, почему COMSOL дает базовый трансторакальный импеданс порядка `100+ Ом` вместо экспериментальных `~12.7 Ом`.

Дата фиксации: 2026-07-08.

> **Дополнение 2026-08-05: расхождение, скорее всего, отсутствует.** Эталонное значение `Z1_TRKG = 12.703 Ом`, вокруг которого построен весь разбор, принадлежит каналу 1 прибора МГТУ. Этот канал даёт заведомо неверные абсолютные значения: на одном и том же трансторакальном монтаже, с одинаковым расположением электродов, измерение исправным прибором в РНЦХ даёт `93–101 Ом` при отключённом втором канале и `54 Ом` при обоих включённых, тогда как прибор МГТУ показывает медиану `11.9 Ом` (размах `9.97–12.33` по девяти записям Ника). Расчёт COMSOL `100+ Ом` совпадает с исправным измерением одиночной токовой пары.
>
> Отсюда: гипотезы этого разбора — ошибка единиц `rho`, завышение геометрического множителя, деление `rho` на десять — устраняют расхождение, которого, по-видимому, нет. Остаточное отличие расчёта от измерения при обоих включённых каналах (`100+` против `54 Ом`) объясняется межканальным шунтом: подключённый второй канал добавляет через входные цепи прибора проводящий путь между двумя точками тела.
>
> Разбор и вывод — [Colab Notebooks/17](../Colab%20Notebooks/17_Дрейф_опорного_канала_и_порядок_съёмки.ipynb), §4.1 и §4.2. Утверждение имеет статус гипотезы с сильной поддержкой: прямого измерения трансторакального импеданса Ника исправным прибором пока нет, а площадки различаются ревизией прибора. До такого измерения выводы ниже сохраняются как есть и не пересматриваются.

## Правило для новых расчетов

Каждый новый COMSOL-расчет должен сопровождаться экспортом проверочных PNG:

- геометрия;
- назначение материалов;
- Terminal/Ground или point source/sink;
- области усреднения напряжения;
- отдельный вид, где реально видны электроды или выбранные электродные сущности.

Для однородной серии это уже сделано в `homogeneous_electrode_study/`.

## Исходная постановка

Цель: перейти от экспериментального изменения `Z_TRKG` в начале/конце систолы к изменению радиуса сердца-сферы в COMSOL.

Геометрия:

- тело/мягкие ткани;
- легкие;
- сердце как сфера;
- кости/прочие ткани упрощенно;
- электроды/отверстия в исходной STEP-геометрии.

Рабочие экспериментальные числа для Ника:

- `Z1_TRKG = 12.703 Ом`;
- `Z2_TRKG = 12.626 Ом`;
- `Delta Z = -0.0766 Ом`.

Параметры из текущего пайплайна:

- `rho1 = 4.728174786010649 Ом*м`;
- `rho2_in = 17.73503700425868 Ом*м`;
- `rho2_ex = 14.757855500692623 Ом*м`;
- `h = 0.015 м`;
- `rho2_ct = 17.4067 Ом*м`.

`Kandidatskaya` в этом разборе не использовалась.

## Главное, что выяснили

1. Старый MPH-файл был из более новой версии COMSOL и напрямую в установленном COMSOL 6.0 не открывался. Работали через STEP + Java API.

2. Исправление "сердце-сфера уменьшается, а вокруг остается пустота" сделано через soft filler shell:
   - внешняя сфера `fillOuterRadius = max(Rh_geom, heartRadius)`;
   - внутренняя сфера `heartRadius`;
   - разность назначается мягким тканям.

3. При текущих `rho1/rho2` модель стабильно дает `Z ~133-140 Ом`, в зависимости от варианта электродов.

4. Перемещение электродов/точек на верхнюю часть цилиндров рук само по себе не дает переход к `12 Ом`:
   - старые домены электродов: `133.2455 Ом`;
   - window/body top faces: `138.0746 Ом`;
   - point на верх цилиндра руки: `139.9615 Ом`;
   - small pads сверху: `138.3741 Ом`.

5. Однородная модель с тем же `rho1=4.728 Ом*м` все равно дает `~109 Ом`. Значит основной разлет сидит в геометрическом коэффициенте COMSOL-модели, а не только в неоднородности легких/сердца.

6. Новая однородная серия с экспортом картинок подтвердила тот же порядок для разных электродных постановок:
   - старые домены электродов как металл: `104.2584 Ом`;
   - boundary window на body-top faces: `108.8205 Ом`;
   - point source/sink и point voltage probes сверху на цилиндрах рук: `111.0224 Ом`;
   - видимые small pads около body-top координат: `109.0986 Ом`;
   - видимые small pads сверху на цилиндрах рук: `111.0231 Ом`.

7. Искусственное уменьшение `rho1/rho2` примерно в 10.9 раза подгоняет модель к `12.7 Ом`, но это не доказывает ошибку единиц в `rho`. Это показывает, что произведение `rho * K_geometry` завышено примерно на порядок.

8. Текущий наиболее осторожный вывод:

   `rho1 ~= 4.7 Ом*м` может быть физически правдоподобным, но COMSOL-модель в текущей геометрической/электродной постановке имеет слишком большой геометрический коэффициент для TRKG.

## Почему нельзя просто сказать "rho ошибочно"

`rho1` было восстановлено из локальной электродной матрицы `BASE_2` через плоскую двухслойную модель. Это эффективный параметр для одной измерительной геометрии.

TRKG `BASE_1/RHEO_1` - другая геометрия: ток идет между руками/плечевым поясом и грудным объемом. Для нее нужен свой геометрический коэффициент и корректные электродные boundary patches.

Формально:

`Z = rho * K_geometry`

По эксперименту:

`K_exp ~= 12.7 / 4.728 = 2.69 1/м`

В однородном COMSOL-тесте:

`K_COMSOL ~= 109 / 4.728 = 23.1 1/м`

Отношение:

`K_COMSOL / K_exp ~= 8.6`

То есть вопрос сейчас в первую очередь к геометрии/электродной постановке, а не к одному числу `rho`.

## Что считать надежным

Надежно:

- COMSOL 6.0 умеет импортировать `TTrans_for_NIX.step` через Java API.
- Материалы и домены классифицируются воспроизводимо.
- При текущей постановке COMSOL дает `100+ Ом`.
- Изменение радиуса сердца на миллиметры в этой постановке почти не меняет `Z` (`~0.004-0.005 Ом/мм` в quick sweep).
- Старые электродные домены/отверстия не объясняют весь порядок разлета.

Ненадежно/диагностично:

- `rho/10 -> 12.7 Ом` - это только подгонка масштаба, не доказательство ошибки `rho`.
- Текущий `models/TTrans_NIX_point_radius_6_0_diagnostic.mph` не финальный файл для научного расчета.
- Gaussian skin-current вариант был начат, но Neumann-only постановка зависла на линейном решателе; нужен явный reference/ground или другая устойчивая постановка.
- MATLAB LiveLink-скрипт сохранен как идея проверки, но численно не верифицирован.

## Что делать дальше в GUI

1. Взять `geometry/TTrans_for_NIX.step` или текущую GUI-модель без электродов.
2. Убрать/не использовать старые электродные домены и отверстия как электроды.
3. Создать 4 реальные boundary patches на наружной поверхности цилиндров рук:
   - левый токовый;
   - левый измерительный;
   - правый измерительный;
   - правый токовый.
4. Сначала сделать однородный фантом:
   - все ткани `rho = 4.728 Ом*м`;
   - проверить порядок `Z`.
5. Если однородный фантом все еще дает `100+ Ом`, проблема в форме/пути тока/положении электродов.
6. Только после совпадения порядка базового `Z` добавлять легкие, сердце, кровь и sweep радиуса сердца.
