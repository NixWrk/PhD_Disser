# Проверка эквивалентности Wolfram и Python

Тесты разделяют три разных типа доказательств:

1. точные числа, сохранённые исходным Wolfram-проектом;
2. аналитические свойства формул;
3. самосогласованность и защита API.

Один только третий тип не доказывает правильность переноса. Поэтому
критические преобразования закреплены отдельным
`test_wolfram_regressions.py`.

## Запуск

```powershell
# Весь пакет
python -m pytest -q

# Только строгие регрессии переноса
python -m pytest -q tests/test_wolfram_regressions.py

# Геометрия и объёмы
python -m pytest -q tests/test_geometry_volume.py

# Полный пайплайн
python -m pytest -q tests/test_pipeline.py
```

Текущее ожидаемое состояние: **235 passed**.

Предупреждение `pytest_asyncio` об области видимости event loop приходит
из внешнего установленного плагина и не связано с вычислительным кодом.

## Строгие регрессии

### Округление объёма

Тест использует синтетический цилиндр с неокруглённым объёмом `10.49 мл`.

```text
Wolfram Round[10.49, 1] = 10
Python round(10.49, 1)  = 10.5
```

Дополнительно пациентские объёмы сравниваются оператором `==`:

- Ivan: `485.0 мл`;
- Alex: `604.0 мл`;
- Artem: `622.0 мл`.

Допуск ±0.5 здесь запрещён, потому что он маскирует неправильную семантику.

### Порядок округления Method4

Finder подменяется контролируемым значением. Тест отдельно доказывает:

1. `dr` округлён до `0.0001 м`;
2. после нелинейной формулы с `sqrt` результат не округлён повторно.

Такой изолированный тест не зависит от поведения сеточного поиска.

### Bounds подгонки сферы

Используются идеальные окружности, безусловные оптимумы которых находятся:

- при `x=100`;
- при `y=100`, `r=80`;
- при `r=10`.

Функция обязана вернуть решение внутри области Wolfram. Текущие три
пациента для этого недостаточны: их оптимумы и без ограничений находятся
в допустимой области.

### Дробный шаг

Подмена `get_l_point` записывает все переданные смещения. Для `step=2.5`
ожидается строго:

```text
1, 3.5, 6.0, ..., 101.0
```

Интеграционный тест дополнительно проверяет объём Ivan. Старая реализация
с `int(2.5)` использовала шаг 2 для хорд и 2.5 для высоты слоя, что давало
около `606 мл` вместо `485 мл`.

### Полный `TotalModelling`

Для трёх пациентов сравнивается вся структура `2×2×3`. Это 36 конечных
значений, извлечённых из Output-ячеек
`WolframMath-master/implem/sphereMove/SphereMoveModelling.nb`.

Сравнение выполняется без численного допуска, потому что конечные объёмы
уже квантованы до целых, а SV — до половины миллилитра.

## `reference_values.json`

JSON содержит смесь:

- констант, буквально перенесённых из `.m`;
- вычисленных значений, подтверждённых notebook;
- вспомогательных Python-значений для структурных тестов.

Поэтому JSON не следует целиком называть автоматически сгенерированным
Wolfram Engine эталоном. Скрипт `gen_reference.m` в текущем виде не
воспроизводит структуру этого JSON и не загружает все необходимые
определения.

Полные конечные массивы хранятся непосредственно в строгом тесте, чтобы
их происхождение и назначение были видны рядом с утверждением.

## Когда допустим численный допуск

Допуск оправдан:

- при сравнении результатов `Nelder-Mead` разных реализаций;
- при проверке центроидов и трансцендентных функций;
- для промежуточных неокруглённых `float`.

Допуск не оправдан:

- для дискретного результата табличного finder;
- для массива, явно округлённого Wolfram `Round[..., 0.0001]`;
- для объёма после `Round[..., 1]`;
- для конечного SV, если оба объёма уже целые.

## Протокол обновления эталона

Если тест эквивалентности перестал проходить:

1. не менять ожидаемое число автоматически;
2. локализовать первый разошедшийся промежуточный этап;
3. сравнить соответствующую функцию с `.m`;
4. проверить единицы измерения;
5. проверить сетку, знак, порядок аргументов и округление;
6. при намеренном изменении модели получить новый независимый эталон;
7. описать в документации, почему старый Wolfram-результат больше не
   является целевым.

Новый Python-результат сам по себе не считается независимым эталоном.
