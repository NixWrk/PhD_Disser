# Внутренняя карта пакета `cardio_model`

Этот документ предназначен для разработчика, который меняет формулы или
пытается понять, какое последующее вычисление зависит от конкретной
функции.

Обзор модели, единиц и пользовательские примеры находятся в
[`../../README.md`](../../README.md).

## Направление зависимостей

```text
data ───────────────────────────────────────────────────────────┐
  │                                                            │
  ├──> models <── finders <── radial ───────────────┐           │
  │                                                │           │
  ├──> sphere_fit <── sistole <────────────────────┼── pipeline
  │                     ▲                          │           │
  └──> geometry ────> volume ──────────────────────┘           │
                                                               │
data/mri и data/moves ──────────────────────────────────────────┘
```

Нижние модули не должны импортировать `pipeline.py`. Верхний пайплайн
собирает их, но не содержит новых физических формул, кроме явного перевода
единиц и конечного `(Vd-Vs)/2`.

## `models.py`

| Функция | Рассчитывает | Вход | Выход | Используется далее |
|---|---|---|---|---|
| `one_layer_model` | импеданс однородного слоя | `rho1`, `a`, `b` | Ом | `sphere_model`, тесты |
| `two_layer_model` | импеданс двухслойной среды | два `rho`, `h`, `a`, `b` | Ом | `find_h_two` |
| `sphere_influence` | добавочный импеданс сферы | свойства ткани и геометрия | Ом | `sphere_model` |
| `sphere_model` | полный импеданс канала | `rho1`, `rho2`, `a,b,R,h,x,y` | Ом | все sphere-finders |

Все геометрические аргументы этого модуля задаются в метрах. Изменение
предела ряда или порядка четырёх `Zep`-слагаемых изменит все радиальные
методы и конечный SV.

## `finders.py`

| Функция | Что инвертирует | Основной потребитель |
|---|---|---|
| `find_ro_one` | `OneLayerModel → rho1` | Method2 и Method4 |
| `find_h_two` | `TwoLayerModel → h` | отдельный API |
| `find_r_sphere` | `SphereModel → R` | отдельный API |
| `find_h_sphere` | `SphereModel → h` | отдельный API |
| `find_ro_sphere` | `SphereModel → rho1` | все поиски `dr` при `ro1=0` |
| `find_dr_sphere` | изменение импеданса → `dr` | Method1 |
| `find_dr_sphere_dxdy` | `dZ → dr` при движении центра | отдельный API |
| `find_dr_sphere_fl` | `dZ → dr` с первым слоем | Method2 |
| `find_dr_sphere_fl_dxdy` | `dZ → dr` со слоем и центром | Method4 |

`_tabular_crossing` возвращает левую границу первого пересечения. Замена
его на `root_scalar`, интерполяцию или минимум изменит научную семантику и
потребует новых Wolfram-эталонов.

## `radial.py`

| Функция | Поправка первого слоя | Движение центра | Округление | Потребитель |
|---|---:|---:|---|---|
| `rad_eval_method1` | нет | нет | итог до 0.0001 м | `pipeline.radial_evaluation` |
| `rad_eval_method2` | да | нет | итог до 0.0001 м | `pipeline.radial_evaluation` |
| `rad_eval_method4` | да | да | только внутренний `dr` | `pipeline.radial_evaluation` |
| `rad_eval` | диспетчер Method1/2 | нет | определяется методом | внешний API |

Пять элементов результата соответствуют пяти внутренним точкам
семиточечного контура.

В Method4 `dxdy[:, 1]` идёт в модельный `dx`, а `dxdy[:, 0]` — в `dy`.
Перед моделью оба значения делятся на 1000.

## `sphere_fit.py`

| Функция | Рассчитывает | Используется далее |
|---|---|---|
| `req_for_heart` | радиус сферы по объёму МРТ | вспомогательный API |
| `mass_center_contour` | центроид полигона | Radius/MassCenter методы |
| `circle_radius_by_contour_sqr` | `sqrt(area/pi)` | MassCenter метод |
| `sum_delta` | сумму квадратов радиальных невязок | все NM-подгонки |
| `eq_sph_nm_center_radius` | центр и радиус | `Use_Contour` |
| `eq_sph_nm_radius` | радиус при данном центре | `Use_Contour_Radius` |
| `eq_sph_nm_center` | центр при данном радиусе | `Use_Contour_Center` |
| `equal_sphere` | диспетчер методов | `equal_sphere_move_modelling` |

Единицы — миллиметры. Совместная оптимизация обязана сохранять bounds:

```text
x: [-40, 40], y: [-60, 40], r: [20, 60]
```

Удаление `bounds=bounds` может не проявиться на текущих пациентах, но
разрешит физически другой класс решений.

## `sistole.py`

| Функция | Действие | Используется далее |
|---|---|---|
| `sistole_none` | радиально двигает внутренние точки и края | оба метода систолы |
| `valve_point` | двигает два края по нормали клапана | `valve_contour_move` |
| `valve_contour_move` | заменяет крайние точки | `sistole_valve_move` |
| `sistole_valve_move` | радиальное + клапанное движение | диспетчер |
| `sistole_contour` | выбирает `None`/`ValveMove` | sphere/pipeline |

Входной `move` здесь измеряется в миллиметрах. Радиальный модуль возвращает
метры, поэтому перевод выполняется до вызова `sistole_contour`.

## `geometry.py`

| Функция | Рассчитывает | Выход | Потребитель |
|---|---|---|---|
| `get_coord_after_move` | радиальный сдвиг точек | контур | `volume`, `sistole` |
| `kubic_interpol` | эрмитову интерполяцию | 186 точек для 7 узлов | `volume_by_contour` |
| `get_l_point` | дискретную хорду на высоте | две точки или `None` | список сечений |
| `list_of_parallel_sections` | сетку хорд | список `(2,2)` | `volume_by_section` |

`list_of_parallel_sections` принимает `float`. Значения смещений должны
быть эквивалентны Wolfram `Table` от 1 до 101 включительно, если конечная
точка попадает на сетку.

## `volume.py`

| Функция | Рассчитывает | Выход | Потребитель |
|---|---|---|---|
| `cut_konus_circle_volume` | один слой между кругами | мм³ | `volume_by_section` |
| `volume_by_section` | сумму слоёв | целые мл в `float` | контурный объём |
| `volume_by_contour` | интерполяцию, хорды и объём | целые мл | pipeline |
| `sv_by_contour_and_5move` | упрощённый SV по готовому move | мл | внешний API/тесты |

Округление выполняется внутри `volume_by_section`, то есть до вычисления
разности двух объёмов. Не заменять `round(volume_ml)` на
`round(volume_ml, 1)`: эти выражения имеют разную семантику относительно
Wolfram `Round[x, 1]`.

## `pipeline.py`

| Функция | Получает | Возвращает | Кого вызывает |
|---|---|---|---|
| `dxdy_find` | направление канала и общий move | локальные 2 компоненты | NumPy |
| `h_contour_dxdy_for_each_channel` | пациент и center move | `(5,2)` мм | `dxdy_find` |
| `equal_sphere_move_modelling` | методы сферы/систолы | `(2,)` мм | data, sistole, sphere_fit |
| `radial_evaluation` | одна комбинация | SV, мл | все центральные модули |
| `total_modelling` | имя пациента | `2×2×3` SV | `radial_evaluation` |

`radial_evaluation` вычисляет движение центра даже для Method1/2, хотя оно
не входит в их импедансную формулу. Это повторяет структуру исходного
верхнего алгоритма.

## `data/`

| Источник | Содержимое | Потребители |
|---|---|---|
| `patients.py` | радиальные данные, параметры, 7-точечные контуры | radial, pipeline, tests |
| `mri.py` | контуры с предсердием, клапан, радиус МРТ | pipeline, sistole |
| `imp.py` | временной набор Artem | исследовательские сценарии |
| `moves/*.txt` | пять временных рядов движения | `edge_move_*`, pipeline |

Геттеры не копируют данные. Мутация полученного массива меняет глобальный
набор текущего процесса.

## Заглушки

`dsp.py`, `plotting.py`, `importers/reo32.py` и `importers/comsol.py`
содержат только описание предполагаемого API. Ни один из них не участвует
в `radial_evaluation` или `total_modelling`.

## Если изменяется формула

Минимальный порядок проверки:

1. определить Wolfram-функцию-источник;
2. перечислить всех потребителей по таблицам выше;
3. добавить прямой тест формулы;
4. добавить тест на единицы и пограничный случай;
5. запустить `tests/test_wolfram_regressions.py`;
6. запустить весь `pytest`;
7. объяснить изменение эталона, если меняются 36 конечных чисел.

Нельзя просто обновлять ожидаемые числа под новый Python-результат без
независимого Wolfram-эталона или документированного изменения самой модели.
