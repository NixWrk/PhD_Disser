# Единый MATLAB/Python-pipeline для notebook-отчётов

## Назначение

Папка `MATLAB_TRKG4_real_subjects/` является единственным активным источником
MATLAB-расчётов для notebook-файлов проекта. Notebook-файлы не должны
воспроизводить FEM-решатель внутри Python: они читают явно именованные
артефакты из `output/`, проверяют контракт и оформляют расчёт как отчёт.

Текущий статус всей цепочки — разработка методики, а не завершённая физическая
или клиническая валидация.

## Точка входа

Из корня папки MATLAB:

```matlab
report = run_pipeline('Profile', 'preflight');
report = run_pipeline('Profile', 'inverse_report');
```

Профиль `inverse_report` последовательно выполняет:

1. проверку MATLAB/EIDORS/Gmsh и обязательных входов;
2. модульные тесты;
3. расчёт двух валидных боковых электродных систем на одной сетке;
4. обратную задачу по многоразмерной серии на вдохе;
5. быстрый PEM-поиск;
6. CEM-уточнение;
7. контроль пересечения электродных патчей.

По умолчанию результаты пересчитываются. Использование уже существующих
файлов разрешается только явно:

```matlab
report = run_pipeline('Profile', 'inverse_report', ...
    'ReuseExistingResults', true);
```

При каждом запуске создаются CSV- и JSON-манифесты стадий. Они фиксируют
исполнителя расчёта, статус, длительность и ожидаемые артефакты, но не заменяют
provenance входных медицинских данных и commit SHA.

выше обязательны. Два нетегированных CSV старой сетки v4 необязательны: при
их отсутствии пропускается только историческое сравнение сеток.

## Контроль сдвига обратного решения

После перепрогона от 01.09.2026 точка обратной задачи заметно сместилась.
Причины проверены отдельными расчётами, в которых по одному сохранялись или
заменялись входной размерный ряд, параметры и алгоритм контактных площадок.

Установлено следующее.

1. В исходных CSV значения импеданса не изменились. Для Ника исправлена только
   субъектная атрибуция одинаковых записей: независимой считается запись 90 мм,
   а поздняя копия 100 мм исключается.
2. При фиксированной прежней точке замена 100 на 90 мм изменила RMSE с 7,763
   до 7,683 Ом и полный критерий с 22,662 до 23,180. Этого недостаточно, чтобы
   объяснить пространственный уход решения.
3. При тех же параметрах, прежнем размерном ряде и неизменной объёмной сетке
   текущий алгоритм построения контактных площадок изменил FEM-кривую на
   5,420 Ом RMS; максимальное отличие 11,802 Ом получено для сборки 50 мм.
   Архивный RMSE 3,593 Ом относится к прежней дискретизации контакта и не
   воспроизводится простым возвратом старых параметров.
4. Для проверки восстановлены два исторических режима. Режим `legacy`
   повторяет самый ранний алгоритм, который независимо наращивал каждое пятно
   и допускал общие узлы электродов. В прежней точке он дал RMSE 21,015 Ом:
   результат 50-мм сборки увеличился до 148,142 Ом. Режим `legacy_fast`
   функционально воспроизводит более поздние правила: ближайшие грани без
   разбиения поверхности между электродами, запрет повторного использования
   узлов и остановка по площади явно выбранных граней. Его исходный файл в
   доступной истории не сохранился, поэтому режим является реконструкцией.
5. Реконструкция `legacy_fast` совпала с архивной геометрией для 34 из 36
   электродных пятен. Остались два краевых расхождения для `V_minus` при 50 и
   70 мм: максимальное смещение центроида составило 0,619 мм, а отличие
   площади — 1,732 мм². При фиксированных архивных параметрах этот режим дал
   RMSE 3,997 Ом и `J=13,114`. Семь из девяти значений импеданса совпали с
   архивом точно; для 50 мм получено 94,034 вместо 79,108 Ом, для 70 мм —
   89,811 вместо 88,785 Ом. Следовательно, работоспособная функциональная
   версия прежнего алгоритма восстановлена, но точное происхождение двух
   архивных пятен и RMSE 3,593 Ом остаётся неустановленным.
6. Проверка MAT-файлов показала: `nodes`, `elems`, `boundary`, `elem_sigma`,
   `tissue_id` и `tissue_names` двух файлов v5 совпадают поэлементно. Различие
   хэшей контейнеров связано с другими полями и метаданными, а не с изменением
   объёмной прямой модели.
7. Выполнен возобновляемый прямой поиск с несколькими начальными областями и
   одинаковым верхним бюджетом 100 FEM-оценок. `legacy_fast` достиг заданного
   разрешения шага после 70 оценок: `J=10,5237`, RMSE 3,952 Ом,
   $(u,v,\varphi)=(5,656; 26,230; -10°)$. Центр совпал с архивной точкой;
   изменилась главным образом $\rho_2$ до 21,977 Ом·м. Текущий `disjoint`
   использовал 100 оценок: `J=11,0160`, RMSE 4,068 Ом,
   $(u,v,\varphi)=(5,880; 26,655; -6,875°)$ и $\rho_2=24,707$ Ом·м.
   Его центр отстоит от архивного на 0,480 мм в касательной плоскости.
8. Бюджет 25 точек оказался недостаточным. К этому моменту `legacy_fast` уже
   дал `J=10,5285`, но для `disjoint` было найдено только `J=15,3326`;
   итоговая область появилась позднее. Три точки `disjoint` оказались
   геометрически недопустимыми: связную площадку требуемой площади нельзя было
   построить без пересечения с соседним электродом. Они сохранены в истории со
   штрафом и не использованы как конечные решения.
9. Резервный `fmincon` не подходит для самостоятельного поиска позы. Выбор
   конечного набора поверхностных граней делает зависимость от координат и
   угла кусочно-постоянной. Микроскопический шаг конечных разностей не видит
   смены граней: угол сохраняет стартовое значение, а движение по координате
   может определяться главным образом штрафом за CT-глубину.
10. CEM-кандидат, рассчитанный при фиксированных `rho` из неудачного локального
   прогона, сохраняется только как диагностический. Его нельзя передавать как
   итоговую локализацию без совместной повторной оценки всех параметров.

`run_trkg4_inverse_inhale` всегда сохраняет отдельную историю вычисленных
точек. При остановке по лимиту в итоговый файл должна попадать точка с
наименьшим конечным значением критерия среди фактически рассчитанных, а не
последняя принятая итерация решателя. Для неразрушающих контрольных прогонов
предусмотрены отдельные `data_selection` и `result_tag`; они не изменяют
канонические файлы v5.

Режимы `legacy` и `legacy_fast` предназначены только для проверки
происхождения архивных чисел. Они не заменяют текущий режим `disjoint`, в
котором электродные пятна связны, разделены по области ближайшего центра и
контролируются по фактической площади поверхности, используемой полной
электродной моделью. Близость RMSE исторического варианта сама по себе не
подтверждает физическую корректность его контактной геометрии.

Расширенный поиск устранил ложный большой пространственный сдвиг и локализовал
обе новые точки рядом с архивной областью. Это локальная вычислительная
устойчивость в пределах проверенных стартов и шага, а не доказательство
единственности или физической истинности решения.

Для `TRKG4_inverse_inhale_results.ipynb` каноническими входами основного
результата являются файлы с тегом `disjoint_restartable_manifest90`:
сводка подгонки, кривая импеданса, профиль глубины, геометрия электродов,
геометрия сетки, Якобиан и локальная чувствительность. Файлы с тегом
`v5_1mm_local2mm`, архивный снимок до перепрогона и старый PEM/CEM-скрининг
используются только в сравнительных разделах. В 3D-графиках итоговая
координата `disjoint` показывается вместе со старой архивной координатой, но
архивная точка не участвует в новом расчёте.

Полный сравнительный раздел 18 удалён из читательской версии отчёта после
перевода основных разделов на `disjoint`: он повторял результаты разделов 10
и 14 и мог восприниматься как второй способ расчёта. Старые `legacy_fast`,
`v5_1mm_local2mm`, `ablation_*`, PEM/CEM и снимок
`output/repro_check_20260901_before/` сохранены локально для аудита
происхождения результата, но не считаются равноправными итоговыми оценками.

DICOM не является входом MATLAB/FEM-конвейера. Для наложения HU в отчёте
локально задаётся `KALMYKOV_DICOM_DIR`; без этой переменной отчёт продолжает
работу по STL и расчётным CSV. Абсолютный путь к медицинским данным в коде
не хранится.

## Параметрический монтаж на руках

Профиль запускается отдельно:

```matlab
report = run_pipeline('Profile', 'arm_electrode_report', ...
    'ArmPrebuiltMeshFile', 'output/accepted_arm_parameter_mesh.msh', ...
    'ArmMeshTargetSizeMm', 1);
```

Файл сетки обязателен. Для этого профиля принят
`output/accepted_arm_parameter_mesh.msh`: 752 827 узлов и 4 358 825
тетраэдров, целевой шаг 1 мм в рабочих объёмах обеих рук. Pipeline не
подменяет сетку молча и не запускает профиль без явно указанного файла.
Критерии приёмки и команды воспроизведения приведены в
[`ARM_PARAMETER_MESH_ACCEPTANCE.md`](ARM_PARAMETER_MESH_ACCEPTANCE.md).

Диагностический равномерный 1-мм прогон от 31.08.2026 построил сетку на
5 601 998 узлов и 33 866 614 тетраэдров с объёмом 20,1663 л. Геометрический
объём сохранился с расхождением около 0,022%, но были найдены вырожденные и
инвертированный элементы, а размер сетки примерно в 47 раз превысил прежний.
Эта сетка отвергнута и не используется в расчётах.

### Поверхностные координаты электродов ТТРКГ

Общее задание координат и ограничения метода описаны в ноутбуке
`Colab Notebooks/40.03_Поверхностные_координаты_электродов_ТТРКГ.ipynb`.
Частный конечно-элементный тест электродов на руках остаётся в `40.02`.

Система `surface_path_v1` использует всю внешнюю поверхность тела. Она
предназначена для четырёхэлектродного монтажа ТТРКГ и не используется для
боковых сборок мягких тканей, РЕО32 или стандартной ТРКГ. Общий механизм
принимает четыре произвольные координаты, проецирует их на границу FEM-модели и
строит контактные площадки. Он уже применяется к монтажам на руках и на правом
боку.

Интерактивный файл `output/nik_surface_landmark_picker.html` построен
скриптом `tools/build_surface_landmark_picker.py`. Основной режим
позволяет выбрать четыре именованные точки на любом участке внешней
поверхности. Дополнительный симметричный режим использует два независимо
заданных пути для сторон I+/V+ и I-/V-. Равными задаются расстояния от
соответствующих анатомических ориентиров до внутренних электродов и расстояния
между внутренними и внешними электродами. Зеркальное отражение XYZ не
используется.

Интерфейс создаёт `ttrkg_surface_montage.json` по схеме
`trkg4_ttrkg_surface_v3`. Свободно выбранные центры обрабатываются
существующим общим механизмом проекции на поверхность. Для симметричного режима
точные центры повторно вычисляет `trkg4_surface_montage_centres` на
исходной расчётной поверхности. Предварительные точки HTML служат только для
визуального контроля.

Скелет, лёгкие и сердце представлены независимыми справочными слоями.
Облегчённая до 12 000 треугольников поверхность и визуальная светотень не
изменяют исходную STL, принятую объёмную сетку или сохранённые результаты FEM.

Программные тесты проверяют генератор HTML, контракт MATLAB-загрузчика,
вычисление центров по поверхностным путям и сохранение прежнего контракта монтажа на руках.
Автоматизированная браузерная проверка подтвердила оба режима: свободный выбор
четырёх точек и последовательность «две направляющие → два расстояния → четыре
центра → JSON». Эти проверки подтверждают программную согласованность, но не
правильность выбранных анатомических ориентиров.

Частный профиль параметрического монтажа на руках сохраняет отдельные
ограничения. На принятой сетке автоматический перенос прежнего начала отсчёта
дал расхождение центров до 7,85 мм. Прежняя внутренняя плоскость присоединения
искусственной руки не задаёт однозначную точку на коже. Поэтому перед заменой
действующего осевого монтажа на руках необходимо принять опорную границу на каждой
руке, проверить пути, построить электродные патчи и повторить проверку
взаимности. Этот отрицательный результат относится к частному профилю монтажа на руках и не
ограничивает общий механизм привязки к внешней поверхности тела.

## Подготовка и QC геометрии

Историческая операция равномерного remesh перенесена в общий скрипт:

```powershell
python tools/remesh_stl_uniform.py input.stl output.stl `
  --cell-size-mm 1 --report output/remesh_report.json
```

MeshFix отключён по умолчанию. Он включается только явно и его результат
отклоняется при превышении заданного изменения объёма:

```powershell
python tools/remesh_stl_uniform.py input.stl output.stl `
  --cell-size-mm 2 --repair meshfix --max-volume-change-percent 0.5
```

Проверка объёмной сетки:

```powershell
python tools/check_msh_quality.py output/model.msh `
  --report output/model_mesh_qc.json
```

Без `--allow-defects` команда возвращает ошибку при наличии инвертированных
или вырожденных тетраэдров.

## Активный код и история

- `src/` — точки входа и логика текущей TRKG4-постановки;
- `vendor_stl_eidors/` — используемые проверенные EIDORS/STL-helper-функции;
- `tools/` — активная подготовка и QC STL/MSH;
- `tests/` — модульные тесты;
- `archive/MATLAB_investigation_NIX/` — ранний прототип и старые sweep-скрипты.

Архив не является вторым способом получить актуальные числа. Его старые
16-электродные кольцевые постановки, единицы и sweep-отчёты сохраняются только
для происхождения решений и критического аудита.
