# Локальная конфигурация внешних данных

В репозитории хранится только схема конфигурации. Реальные пути, имена
каталогов испытуемых и производные медицинские данные остаются вне Git.

## Эксперимент 1

1. Скопируйте `exp01_paths.example.json` в `exp01_paths.local.json`.
2. Заполните внешний корень записей РЕО32 и внешний корень производных данных.
3. Задайте `KALMYKOV_EXP01_CONFIG` с абсолютным путём к локальному JSON.

## Эксперимент 2

1. Скопируйте `exp02_paths.example.json` в `exp02_paths.local.json`.
2. Заполните внешний корень CSV, внешний корень производных данных,
   обезличенные идентификаторы, размеры и относительные подкаталоги.
3. Задайте `KALMYKOV_EXP02_CONFIG` с абсолютным путём к локальному JSON.

Поля `legacy_timestamps_dir`, `legacy_params_dir` и `legacy_subject_key`
нужны только объединённым ноутбукам, которые ещё не переведены на новые
sidecar-контракты. Они не являются интерфейсом целевой архитектуры.

Ноутбуки серии `11` записывают дыхательную и ЭКГ-разметку в разные внешние
подкаталоги. Артефакт становится допустимым входом последующих расчётов только
после ручного контроля качества и установки статуса `accepted`.

## Эксперимент 3

Для эксперимента 3 используется `exp03_paths.example.json` и переменная
`KALMYKOV_EXP03_CONFIG`. Каждая запись получает обезличенный `record_id`,
собственную колонку дыхательного сигнала и собственную последовательность
режимов. Порядок эксперимента 2 не копируется.

## КТ

Для КТ используется `ct_paths.example.json` и переменная
`KALMYKOV_CT_CONFIG`. Локальная схема содержит внешние пути, обезличенные
идентификаторы и явно прослеживаемые субъектно-специфические параметры.
Производные файлы КТ записываются во внешний `derived_root`, а не в `params/`
репозитория.

Все `*.local.json` исключены из Git. Не добавляйте в примеры реальные пути,
имена, даты рождения, номера исследований или другие идентификаторы.
