# Происхождение эталонных значений

## Классы источников

В тестах используются три класса значений.

### Константы исходного кода

`dZRad`, `zBase`, геометрические параметры, контуры, `ValveMove` и файлы
движений перенесены буквально из `.m` и `.txt`.

| Python-данные | Wolfram-источник |
|---|---|
| `data/patients.py::RADIAL` | `RadialEvaluation.m::Get*Radial` |
| `data/patients.py::PARAMS` | `RadialEvaluation.m::Get*Param` |
| `data/patients.py::CONTOURS` | `VolumeCalc.m::*7pointContour` |
| `data/mri.py` | `MRIdata.m` |
| `data/moves/*.txt` | `Kernel/core/*.txt` |

### Численные результаты notebook

Сохранённые Output-ячейки
`implem/sphereMove/SphereMoveModelling.nb` содержат результаты вызовов
Wolfram для пациентов. Из них подтверждены, в частности:

- центры и радиусы эквивалентных сфер;
- массивы радиальных методов;
- пациентские объёмы;
- полные массивы `TotalModelling`.

Все 36 конечных чисел закреплены в
`tests/test_wolfram_regressions.py`.

### Структурные Python-значения

Часть полей `tests/reference_values.json` используется для проверки форм,
длин массивов или промежуточной самосогласованности. Такие значения нельзя
считать независимым доказательством эквивалентности.

## Ограничение `gen_reference.m`

Текущий `WolframMath-master/gen_reference.m` не является полностью
воспроизводимым генератором имеющегося JSON:

- он вызывает `SphereModelTest`, но не загружает содержащий его
  `SphereModel.m`;
- схема формируемой Association не совпадает со структурой фактического
  `tests/reference_values.json`.

Поэтому в документации не утверждается, что весь JSON автоматически
получен одним запуском Wolfram Engine.

## Критическая семантика эталонов

### `Round[x, 1]`

В Wolfram это округление до ближайшего числа, кратного единице. Для
объёмов ожидаются целые миллилитры.

### `Round[x, 0.0001]`

В Method1/2 округляется возвращаемый `dr`. В Method4 округляется
промежуточный `dr`, после чего применяется неокруглённое геометрическое
преобразование.

### Оптимизация

Результаты Nelder-Mead могут не совпадать побитово между Wolfram и SciPy.
Сравниваются физически значимые координаты и радиус с обоснованным
допуском, а ограничения области проверяются строго.

### Конечный SV

Так как контурные объёмы квантуются до целых до вычитания, конечный SV
имеет шаг 0.5 мл. Для сохранённых массивов `TotalModelling` применяется
строгое равенство.

## Обновление

При появлении активированного Wolfram Engine рекомендуется:

1. исправить загрузку пакетов в генераторе;
2. определить единую документированную JSON-схему;
3. сохранить версию Wolfram Engine и hash исходных `.m`;
4. генерировать эталон в новый файл;
5. сравнивать новый файл со старым до замены;
6. не использовать Python-функцию для генерации эталона самой себе.
