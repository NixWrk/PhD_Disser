# Предварительный статус инвентаризации КТ

Дата снимка: 2026-07-16.
Статус: архивы продолжают извлекаться; числа ниже не являются финальным manifest.

## Внешний источник

- 8 RAR-архивов;
- на момент последней проверки создано 4 распакованных каталога;
- источник используется только для чтения;
- имена каталогов и соответствие реальным людям не коммитятся.

## Предварительный ограниченный scan

Scanner просмотрел первые 2000 файлов-кандидатов в доступной на тот момент распакованной части:

- 28 CT-серий;
- 199 DICOM-контейнеров;
- 44 411 CT-кадров;
- 28 из 28 серий представлены как Enhanced Multi-frame CT;
- 0 дублирующихся SOPInstanceUID;
- 0 серий с несколькими вариантами геометрии внутри уже просканированного набора.

## Геометрия

Pixel spacing и slice thickness находятся не в классических верхнеуровневых тегах, а в:

~~~text
SharedFunctionalGroupsSequence
  → PixelMeasuresSequence
~~~

Scanner поддерживает этот вариант и фиксирует источник значения в manifest.

В предварительном scan присутствуют:

- тонкие реконструкции с толщиной 0,5 мм;
- толстые реконструкции с толщиной 5,0 мм;
- несколько значений in-plane pixel spacing примерно от 0,388 до 0,49 мм.

Это означает, что один и тот же scan может иметь несколько реконструкций. Перед конвертацией необходимо выбрать primary series по заранее заданному правилу; 5-миллиметровые серии нельзя автоматически объединять с тонкими.

## Что делать после окончания распаковки

1. Убедиться, что число каталогов и файлов стабильно в двух последовательных проверках.
2. Запустить полный scan без max-files.
3. Создать локальную таблицу соответствия архивов псевдонимам P01–P03/U01–U03.
4. Проверить SeriesDescription и ProtocolName локально, не публикуя их до ручной проверки.
5. Определить вдох, максимальный выдох и возможный спокойный выдох.
6. Выбрать thin-slice primary reconstruction для каждой фазы.
7. Проверить coverage, frame count, spacing, kernel и наличие контраста.
8. Только после этого запускать dcm2niix.
