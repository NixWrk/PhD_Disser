# Подготовка и запуск анализа электродных комбинаций

Документ относится к этапу 40.06 и дополняет существующую цепочку MATLAB/EIDORS/Python. Это интерфейс расчёта чувствительности действительной скалярной проводимости при фиксированной геометрии. Код не восстанавливает анатомию по описанию контактов и не переводит проводимость в объём крови.

## Состав реализации

| Файл | Назначение |
|---|---|
| `src/trkg4_export_sensitivity_model.m` | Экспорт уже подготовленной SI-модели EIDORS, объёмных блоков и CEM-матрицы контактов |
| `src/run_trkg4_electrode_sensitivity.m` | MATLAB-вызов Python через канонический профиль |
| `tools/electrode_sensitivity_contract.py` | Структурная проверка параметров, состояний и каналов |
| `tools/run_electrode_sensitivity.py` | Решение нескольких правых частей, поля, карты, производные и численный контроль |
| `tools/compartment_sensitivity.py` | Поэлементная чувствительность и объёмно-взвешенные сводки |
| `tools/sensitivity_probes.py` | Локальная область с заданным эффективным объёмом и её матрица возмущения |

| `tools/build_electrode_sensitivity_preparation_report.py` | Формирование отдельного отчёта 40.06 |

## Контракт исследования

Пример находится в `configs/electrode_sensitivity_study.example.json`. Его геометрия условна, а нулевые контрольные суммы являются заполнителями. Такой пример не может пройти проверку реальных входов и не запускается как физический расчёт.

- `source` задаёт подготовленный FEM-файл, его SHA-256 и частоту. Пути в JSON относительны к самому JSON-файлу.
- `parameters` сопоставляет именованные проводимости с непересекающимися списками индексов объёмных блоков. Индексы блоков начинаются с нуля. Все экспортированные блоки должны быть покрыты ровно один раз. Проводимость задаётся в См/м.
- `states` содержит полный набор проводимостей каждого состояния. Фиксированные параметры должны совпадать с номинальными.
- `montages` задаёт CEM-матрицы физических контактов, контрольные суммы, упорядоченные имена электродов и происхождение геометрии.
- `channels` задаёт токовый `drive` и измерительный `measure` векторы в порядке имён электродов. Положительные веса каждого вектора суммируются в 1, отрицательные — в −1. Нормировка тока на 1 А является вычислительной.
- `analysis.map_states` перечисляет состояния с сохранением поэлементных карт. `analysis.save_fields` включает сохранение полных прямых и взаимных полей. Число электродов не зафиксировано четырьмя.

Имена параметров, состояний, монтажей и каналов должны быть безопасными идентификаторами. Идентификатор канала допускается повторять у разных монтажей. Валидатор отклоняет пустые блоки, несогласованные состояния, небалансные токи, нечисловые и бесконечные значения, абсолютные пути и неизвестные поля.

## Подготовка нового физического монтажа

1. Получить конечную модель EIDORS с фактически построенными контактными поверхностями и провести геометрический QC. Выбор произвольных координат, формы и площади контактов принадлежит существующим инструментам подготовки соответствующей экспериментальной ветки.
2. Передать в `trkg4_export_sensitivity_model` модель в метрах, метки тканей, имена тканей и непересекающиеся группы элементов для объёмных блоков. Экспорт не преобразует единицы автоматически и не исправляет геометрию.
3. Проверить отчёт экспорта: сумма объёмных блоков и контактной матрицы сопоставляется с EIDORS при единичной проводимости. Контактный файл содержит SHA-256 именно того подготовленного FEM-файла, к которому он относится, и упорядоченный список идентификаторов электродов. Список должен совпадать с контрактом исследования.
4. Заполнить контракт исследования реальными путями, хэшами, параметрами и комбинациями каналов. Сначала выполнить опорное состояние, проверить карты и контактную геометрию, затем расширять набор состояний.

Минимальный пример экспорта, когда каждому компартменту соответствует один объёмный блок:

```matlab
groups = arrayfun(@(k) tissue_id == k, 1:numel(tissue_names), ...
    'UniformOutput', false);
export_report = trkg4_export_sensitivity_model( ...
    fmdl_m, tissue_id, tissue_names, groups, 'output/new_montage_export');
```

Метки тканей должны последовательно покрывать 1…N, а логические маски групп — каждый элемент ровно один раз. Выходной каталог должен быть новым или пустым. Идентификаторы контактов в экспорте имеют вид E1…EN и соответствуют порядку `fmdl_m.electrode`; анатомические названия и геометрическое происхождение следует описать в конфигурации исследования.

Старый экспорт 40.05 принимается по отдельной проверяемой ветке совместимости: подготовленная модель связывается с `identity.json`, контактный файл — с `result_integrity.json`. Одного совпадения размеров матрицы недостаточно.

При сохранении контактных матриц для нескольких монтажей необходимо обеспечить тождественную нумерацию и геометрию узлов объёмной модели. Добавление физически присутствующего электрода меняет CEM-постановку даже при нулевом суммарном токе через него. Перестановка ролей при неизменном наборе контактов меняет правые части, но не контактную матрицу.

## Канонический запуск

Из `MATLAB_TRKG4_real_subjects`:

```matlab
report = run_pipeline('Profile','electrode_sensitivity', ...
    'StudyFile','output/exploratory/electrode_sensitivity_20260910/pilot_combinations.json', ...
    'OutputDirectory','output/exploratory/electrode_sensitivity_20260910/pilot_combinations_verified', ...
    'PythonExecutable','python', ...
    'DependenciesDirectory','output/exploratory/arm_sigma_20260908/python_solver_deps', ...
    'Threads',4);
```

`PythonExecutable` и `DependenciesDirectory` относятся к локальному окружению; указанный пример использует ранее подготовленное окружение этого проекта. Для другого компьютера они задаются явно. Автоматической установки пакетов нет. Прямой Python-вызов того же ядра:

```text
python tools/run_electrode_sensitivity.py --study STUDY.json --output OUTPUT --deps DEPENDENCIES --threads 4
```

Нужны NumPy, SciPy, h5py и pypardiso с доступной MKL. Читательский отчёт использует также pandas, matplotlib и Jupyter. Входы и точные версии кода фиксируются в паспорте; использованные исходники сохраняются архивом. Завершённый прогон повторно принимается только при совпадении идентичности и контрольных сумм результатов. Иная или незавершённая папка не перезаписывается: для нового исследования используется новый каталог.

## Результаты и единицы

- `channel_results.csv`: знаковый передаточный импеданс, взаимность, невязка, размерные производные, условные отклики на 1% и относительные коэффициенты, если нормировка допустима.
- `compartment_maps.csv`: объём, знаковый интеграл, средняя плотность, положительный и отрицательный интегралы, интеграл модуля и компенсация знаков.
- `map_geometry.npz`: центры и физические объёмы всех элементов, метки тканей. Геометрические данные не являются разрешением на публикацию индивидуальной анатомии.
- `*_fields.npz`: полные нормированные поля, включая электродные степени свободы; первые строки соответствуют тканевым узлам.
- `*_sensitivity.npz`: производная по проводимости каждого элемента и её плотность. Нумерация элементов соответствует исходной модели; число элементов не используется вместо физического объёма.
- `identity.json`, `source_used.zip`, `completion.json`, `completion.sha256`: происхождение, версии и контрольные суммы.

Производная по проводимости имеет единицы Ом/(См/м), её плотность — Ом/[(См/м)·м³]. Преобразование плотности к единице объёма 1 мл выполняется делением на 10^6. Потенциалы нормированы на ток и представлены в Ом.

Относительная нормировка отключается при модуле импеданса не выше 10^−8 Ом + 10^−6 от максимального модуля импеданса каналов данного состояния и монтажа. Это диагностическое правило численного представления, а не порог регистрации конкретного прибора. Размерные результаты сохраняются.

## Локальные возмущения и проверки

`select_volume_probe` выбирает элементы по расстоянию их центров, а вес последнего элемента обеспечивает заданный эффективный объём. Полный объём выбранных элементов может быть больше. Частичный вес соответствует равномерно уменьшенному изменению проводимости внутри элемента и не является точным отсечением геометрической границы.

Контрольный пример использует три области по 10 мл и одинаковое абсолютное изменение проводимости +0,001 См/м. Для одной сердечной области вычисляются четыре прямых решения с шагами ±0,001 и ±0,0005 См/м. Эти величины являются техническими масштабами проверки. Локальные области других положений можно задавать через явный центр; их физиологический смысл требует отдельного обоснования.

Сходимость сетки и устойчивость к положению/площади/контакту проверяются для конкретного нового монтажа. Эти проверки не объявляются выполненными по результатам регрессии старой сетки. Законы изменения объёма камер, воздушности и кровенаполнения также не включаются автоматически в производную по эффективной проводимости.

## Выполненная приёмка этапа подготовки

Пройдены 42 Python-теста и 9 подслучаев; четыре MATLAB-теста проверяют настоящий экспорт модели EIDORS с шестью треугольными CEM-контактами, неравными тканевыми проводимостями и отказом от ошибочных входов. Такой экспорт дополнительно прочитан Python-расчётом: решены три канала, в том числе с распределёнными токовыми весами, и сохранены карты.

На модели Nix выполнены 20 сопоставлений для трёх каналов и четыре прямых решения локального возмущения; ещё восемь сопоставлений относятся к восстановлению исходной карты из сохранённых полей. Малые примеры и Nix имеют отдельные паспорта. Итоговая сводка подготовки находится в локальном каталоге результатов, в `preparation_validation.json`.
