# Исследовательская отчётность

Эта папка содержит первичные карточки исследования. Производные отчёты создаются автоматически в `generated/` и вручную не редактируются.

## Структура

- `hypotheses/` — проверяемые гипотезы (`HYP`);
- `protocols/` — версии протоколов (`PROT`);
- `runs/` — фактические запуски (`RUN`);
- `results/` — результаты и интерпретации (`RES`);
- `decisions/` — решения (`DEC`);
- `corrections/` — исправления и замены (`COR`);
- `claims/` — научные положения и заготовки для диссертации (`CLM`);
- `legacy/` — ретроспективно восстановленные записи;
- `templates/` — шаблоны первичных документов;
- `generated/` — автоматически построенные истории, реестр HTML, сами HTML и манифесты.

Это полный перечень предусмотренных категорий. Подпапка создаётся при появлении первой записи соответствующего типа; сейчас существуют `claims/`, `legacy/` и `templates/`. Инструмент обходит `research/` рекурсивно и опирается на поле `record_type` внутри записи, а не на её расположение, поэтому отсутствие папки не является ошибкой.

Полные требования описаны в [правилах](../Colab%20Notebooks/ПРАВИЛА_ОПИСАНИЯ_РАСЧЁТОВ.md).

## Команды

Из каталога `Калмыков`:

```powershell
python tools/research_report.py validate
python tools/research_report.py build
python tools/research_report.py update
python tools/research_report.py sync --dry-run
```

`update` проверяет записи, строит отчёты, экспортирует сохранённые ноутбуки в HTML и публикует Markdown/HTML в зеркало, заданное в `research-report.json`. Публикация по умолчанию разрешена только при чистой рабочей копии Git. Ручной флаг `--allow-dirty` создаёт только явно помеченный черновой снимок; задача по расписанию его не применяет.

Публикация дополнительно ограничена постоянным `project_id` и веткой `publish_branch`; это не позволяет другой копии проекта, другой ветке или `detached HEAD` занять то же зеркало.

Для установки локальной задачи Windows, запускающей `update` каждые 15 минут:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/install_research_reporting_task.ps1
```

Задача не запускает несколько экземпляров одновременно. Диск `Z:` должен быть подключён в сеансе того же пользователя. В зеркале управляется только подпапка `Репозиторий/Калмыков`; существующие ручные документы в корне кандидатской не затрагиваются.

Зеркало является закрытым внутренним архивом и может содержать исходные идентификаторы; Markdown и HTML получают явную маркировку конфиденциальности. Квитанция последнего фонового запуска находится в `research/generated/scheduled-run.json`. Она различает завершённую синхронизацию, отсрочку из-за незакоммиченных изменений и ошибку; завершённая публикация связывается с архивным манифестом общим `transaction_id`.

Тесты транзакционного отката и восстановления:

```powershell
python -m unittest discover -s tools/tests -p "test_*.py" -v
```

## Порядок новой работы

1. Скопировать нужный шаблон и назначить следующий свободный ID.
2. Зафиксировать гипотезу и протокол до основного запуска.
3. После запуска заполнить `RUN`, затем `RES` или `COR`.
4. Выполнить `validate`.
5. Закоммитить первичные записи и код.
6. Выполнить `update` либо дождаться запланированной автоматической задачи.
