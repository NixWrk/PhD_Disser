# Фазовый расчёт импеданса TEPC по 4D-КТ

## Назначение и границы результата

Расчёт сопоставляет TEPC-2–TEPC-7 при одинаковой пофазной анатомии Nix.
Для каждой маски отдельно вычисляются шесть передаточных импедансов и их
изменения относительно первой доступной фазы. Это прямой вычислительный опыт;
он не восстанавливает объём по сигналу и не определяет оптимальную сборку.

Использованы 12 автоматических масок с метками 14–121% R–R. Метки выше 100%
принадлежат следующему интервалу. Временной ряд не замыкается искусственно и
не переносится автоматически в 0–100%. Окно длительностью одного исходного R–R
отсчитывается от первой доступной фазы; все исходные точки также сохраняются.

Маски достигают верхней границы поля обзора. Полнота верхнего отдела сердца
и прилегающих сосудистых структур не подтверждена. Основной пилот использует
доступную маску без достраивания отсутствующих областей. Результат не считается
валидированным откликом полного сердца. Различия со статической ручной маской
могут отражать одновременно фазу, правила сегментации и поле обзора.

## Расчётная модель

- Общая неподвижная FEM-сетка и шесть отдельных четырёхэлектродных монтажей.
- CEM-контакты диаметром 5 мм, частота 50 кГц, действительные проводимости.
- Исходное сердце заменяется мягкими тканями. Лёгкие и кости сохраняются.
  Каждая фазовая маска накладывается заново на этот фон.
- По вложенным наборам 4096 и 16 384 точек вычисляются доли сердечного
  материала в тетраэдрах. В электрический расчёт передаётся второй набор.
- Для каждой фазы EIDORS заново собирает четыре материальные матрицы.
  Контактная матрица повторно используется только для неизменённых сетки,
  физически присутствующих электродов, площади и контактного импеданса.
- Для каждого монтажа выполняется собственная факторизация и решаются
  прямая и взаимная задачи. Между разными монтажами факторизация не переносится.

Совпадение объёмов при переносе маски проверяет интегрирование материала.
Оно не заменяет проверку пространственной сходимости электрического поля.
Невязка, токовый баланс и взаимность проверяют решение системы, но не физическую
валидность модели или точность автоматической сегментации.

## Воспроизведение

Все команды выполняются из корня репозитория в настроенном окружении Python.
Машинные пути задаются только в исключённых из Git локальных JSON.

1. `tools/check_cardiac_cycle_coordinates.py --config <локальный JSON>`:
   проверка общего DICOM-пространства и согласования внесердечных поверхностей.
   Скрипт не оптимизирует регистрацию по сердцу.
2. `tools/prepare_cardiac_cycle_materials.py --config <локальный JSON>`:
   фазовая геометрия, контроль границ, доли материалов и их контрольные суммы.
   Обязательны пути к FEM, каталогу масок, временной таблице, зависимостям и
   каталогу вывода; преобразование RAS-мм в координаты FEM-мм задаётся явно.
3. `tools/heart_cardiac_cycle_electrical.py prepare --materials <материалы>
   --baseline <опорный статический прогон> --output <новый каталог>`:
   проверка происхождения, привязка шести контактов и фиксация плана 72 решений.
4. `tools/heart_cardiac_cycle_electrical.py run --output <каталог>`:
   последовательная сборка EIDORS и решение с ограничением памяти 32 ГиБ.
   Команды 1–4 запускаются с префиксом `python MATLAB_TRKG4_real_subjects/`.
5. После завершения: `python Colab Notebooks/cardiac_4d_segmentation/heart_cardiac_cycle_report.py --build`
   (путь с пробелом нужно заключить в кавычки). Формируются выполненный ноутбук
   40.23 и HTML без исходного кода.

Завершённые состояния проверяются по контрольным суммам при продолжении.
Неполный каталог решения автоматически не перезаписывается: сначала необходимо
разобрать журнал и сохранить след неудачного запуска. Изменение кода, геометрии,
контактов или условий требует нового плана, а не подмены входов текущего прогона.

Локальные исходные КТ, маски, MAT-файлы и конфигурации не включаются в Git.
Читательские графики и обезличенная численная сводка сохраняются вместе с
ноутбуком. Контрольные суммы исполнявшегося кода относятся к его фактическим
байтам, включая окончания строк; Git может нормализовать окончания строк.
При воспроизведении на другой машине создаётся новый паспорт входов.

## Следующие проверки

Перед ранжированием сборок по восстановлению объёма необходимо проверить
верхнюю границу масок, влияние интегрирования материала и пространственной
сетки на Z, затем раздельно и совместно изменить объём, положение и форму.
Ошибка сегментации проверяется независимой разметкой; физическая валидация
требует отдельного сопоставления с измерениями. Наличие 72 решений само по
себе этих проверок не заменяет.
