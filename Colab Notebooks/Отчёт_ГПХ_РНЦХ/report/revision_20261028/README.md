# Согласованная редакция научного отчёта

Здесь готовится редакция по заданию 28.10.2026. [План](PLAN.md), [критический разбор](CRITICAL_REVIEW.md) и [правила авторов](AUTHORING_RULES.md) задают содержание и критерии проверки. Исходные исследовательские главы сохранены в соседней папке `../chapters/`; их научные результаты не заменяются литературной редактурой.

## Состав

- `chapters/` — двенадцать содержательных глав, каждая подготовлена отдельным агентом и проверяется общей редакцией.
- `reviews/` — адресные сведения о проверке источников, исправлениях и ограничениях.
- `front_matter.md`, `conclusion.md`, `appendices.md` — общие части отчёта; их наличие и готовность фиксируются по факту.
- `figures/` — изображения, включённые в сборку, с происхождением в `build_manifest.json`.
- `tools/` — сборка Word и технические проверки; эти скрипты не выполняют исследовательские расчёты.
- `source_snapshot.json` — контрольные суммы исходных глав на указанном этапе. Новые расчёты могут появляться параллельно; их включение требует отдельной сверки.

## Сборка Word

Нужны Python с `python-docx`, `lxml`, `pypdfium2`, Pandoc и установленный Microsoft Word для обновления полей и фактической отрисовки. В текущей работе используется комплектный Python среды Codex; версии и результат сборки сохраняются в сопровождающем реестре. Из корня репозитория:

```powershell
python 'Colab Notebooks/Отчёт_ГПХ_РНЦХ/report/revision_20261028/tools/audit_revision.py'
python 'Colab Notebooks/Отчёт_ГПХ_РНЦХ/report/revision_20261028/tools/build_word.py' --output 'output/gph_report_20261028/report.docx'
& 'Colab Notebooks/Отчёт_ГПХ_РНЦХ/report/revision_20261028/tools/render_word.ps1' -InputDocx 'output/gph_report_20261028/report.docx' -OutputPdf 'output/gph_report_20261028/render/report.pdf' -UpdateAndSave
python 'Colab Notebooks/Отчёт_ГПХ_РНЦХ/report/revision_20261028/tools/render_pages.py' 'output/gph_report_20261028/render/report.pdf'
```

Параметр `--pandoc` позволяет явно указать исполняемый файл. `--partial` предназначен только для промежуточной проверки оформления: частичная сборка не является итоговым отчётом. Формулы преобразуются в редактируемый OMML. Таблицы разворачиваются; внешние научные ссылки сохраняются. Локальные ссылки в читательском документе адресуются к `sources/repo/` сопровождающего архива. После обновления оглавления документ требуется просмотреть постранично.

Штатный renderer навыка документов проверен, но в этой Windows отсутствует LibreOffice. Поэтому используется явная замена: Microsoft Word → PDF → PNG. PDF и PNG служат контролю вёрстки; запрошенный читательский формат — Word.

## Данные и передача

Полный архив аннотированных экспериментальных исходников, протоколов, сегментаций и рабочих скриптов создаётся локально. Состав, размеры, контрольные суммы, статусы и команды описываются в его README и реестре. Первичные медицинские файлы не включаются в Git. Отчёт, код, разрешённые агрегаты и документация фиксируются отдельными содержательными коммитами и отправляются в текущую ветку.

Готовность научной методики и готовность документа — разные состояния. Поставляемый текст должен точно описывать достигнутые результаты и незавершённые проверки, включая переход к УО и ФВ.
