# Отчёт ГПХ РНЦХ и аннотированные исследовательские материалы

Срез научной редакции: 28.10.2026. Комплект предназначен для локального просмотра и проверки происхождения результатов. Первичные КТ, маски, поверхности и физиологические записи содержат индивидуальные медицинские данные. Их включение в этот локальный комплект не означает разрешения на открытую публикацию.

## Начало работы

1. Распаковать внешний ZIP в отдельную папку. Открыть Word или PDF из `report_and_sources.zip`: это основной отчёт. Word содержит редактируемые формулы; PDF фиксирует проверенную пагинацию.
2. Для согласованной структуры данных выполнить `python extract_delivery.py --archives . --output ../ГПХ_распаковано`. Нужен Python 3.10 или новее; дополнительные библиотеки для распаковки не требуются. Выходная папка должна быть новой. По умолчанию распаковываются `core`, `researchstate`, `report_and_sources`.
3. Для дополнительных фаз КТ добавить `--with-ct4d`, для тяжёлых сохранённых FEM-моделей — `--with-recompute`. Эти тома нужны для соответствующих повторных расчётов, но не для чтения отчёта. Полный комплект занимает около 18,1 ГБ до добавления отчёта; для распаковки и сохранения ZIP требуется дополнительное свободное место.
4. Начать с `manifests/core/README.md` и `FILES_ANNOTATED.csv`. В аннотациях каждого файла указаны назначение, тип, единицы, протокол, статус, происхождение и SHA-256. Общая инвентаризация и замечания сохранены в `manifests/inventory/`.

Контрольные суммы томов находятся в `DELIVERY_MANIFEST.json`. Скрипт проверяет SHA-256 каждого выбранного ZIP до извлечения, а ZIP-библиотека — CRC извлекаемых файлов. При совпадении путей прежняя версия сохраняется в `versions/`, а поздняя редакция занимает рабочий путь; все такие случаи перечисляются в `EXTRACTION_REPORT.json`. Исходный архив никогда не изменяется.

## Состав и назначение томов

| Том | Содержание |
|---|---|
| `core.zip` | Исходные записи выбранных экспериментов, протоколы, аннотации и результаты QC; статические КТ и опорные фазы; сегментации, 15 канонических STL; расчётные таблицы; основные программы и конфигурации с указанием применимости |
| `optional_ct4d.zip` | Дополнительные проверенные фазовые КТ для разработки и сравнения; они не являются допустимым скрытым входом метода с одной КТ |
| `optional_recompute.zip` | Тяжёлые сохранённые сетки и модели для повторения соответствующих численных опытов |
| `researchstate.zip` | Зафиксированный дополнительный срез исследования форм и электрической различимости; статус результатов остаётся условным |
| `report_and_sources.zip` | Word, PDF, главы, библиография, рецензии, рисунки и их генераторы; средства сборки и проверки; дополнения к источникам текущей редакции |

Репозиторная структура находится в `workspace/`, внешние исследовательские данные — в `external/`. Ссылки из Word на `workspace/...` разрешаются после совместного извлечения. Контрольные документы каждого тома лежат отдельно в `manifests/<том>/` и не затирают друг друга.

## Применимые программы и перенос конфигурации

Основные точки входа: `workspace/tools/segment_ct_to_stl.py` — экспорт сегментации в STL; `workspace/tools/prepare_ct_fem.py` — единая подготовка КТ-модели к FEM; профили `run_pipeline` в `workspace/MATLAB_TRKG4_real_subjects` — контакты и электрические расчёты. Порядок, команды, версии, подтверждённые результаты запуска и ограничения приведены в аннотациях общего манифеста и `workspace/docs/CT_FEM_PREPARATION_STANDARD.md`. Работоспособность конкретной сохранённой ветки не означает клиническую валидацию её оценок.

Исходные локальные JSON сохранены неизменными и могут содержать пути машины исследования. Для переноса использовать `workspace/Colab Notebooks/Отчёт_ГПХ_РНЦХ/report/revision_20261028/tools/relocate_config.py` с `--manifest manifests/core/ANNOTATED_MANIFEST.json`, при необходимости дополнительными `--manifest`, `--root` равным папке распаковки, `--input` исходного JSON и `--output` нового JSON. Скрипт создаёт копию и журнал; неоднозначные или отсутствующие зависимости остаются явно неразрешёнными. Перед запуском проверить журнал и задать новые выходные каталоги. Автоматический исследовательский перерасчёт при распаковке не выполняется.

MATLAB, EIDORS, Gmsh/Netgen, Python-библиотеки, GPU-среда, веса и лицензии TotalSegmentator устанавливаются отдельно по паспортам. Одна универсальная среда для всех исторических веток не заявляется. Полные исходные DICOM-серии в комплект не входят; используются проверенные производные тома и сохранённое происхождение.

## Ограничения среза

Не включены три файла с несовпавшими контрольными суммами. Отдельно отмечены отсутствующие исторические технические STL и версия одного прежнего генератора; имеющиеся канонические анатомические STL не подменяют недостающие технические файлы. Точные списки находятся в частном манифесте. Автоматические сегментации, кандидатные дыхательные интервалы и условные тканевые параметры сохраняют исходный статус.

КТ, июльская ЭИТ и октябрьские записи не образуют синхронного измерения. Численные проверки и модельные опыты не подтверждают завершённую экспериментальную валидацию УО и ФВ. Отчёт фиксирует прочитанные версии результатов; продолжающаяся расчётная ветка после этого среза требует новой редакции и отдельного включения в комплект.
